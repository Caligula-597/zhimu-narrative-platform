## 1. Executive Summary

三次生成 **overallScore 均为 6.5**，`readyForSync: false`。瓶颈始终卡在：

| 瓶颈维度 | 三次得分 | 含义 |
|----------|----------|------|
| **spoilerSafety** | 5 / 5 / 5 | 玩家本提前写出 forbiddenFacts、指凶或写穿手法 |
| **fairness** | 6 / 6 / 6 | 推理关键信息仅某一角色本可见，无法公聊/线索对齐 |

其它维度有升有降（任务 +1、矩阵/入库 -1），**不足以拉高总分**。

**核心结论**：问题不是「骨架设计差」，而是 **⑥ 写剧本这一步 LLM 无法稳定遵守 spoilerGates / 公平约束**；真凶位尤其容易在内心独白中「自曝」。单靠 prompt 可缓解 innocent 角色泄漏、改善篇幅与命名，**不能单独解决 6.5 → 7.5+**。

## 4. 跨三代共性根因

### 4.1 剧透安全（spoilerSafety = 5）

| 根因 | 说明 |
|------|------|
| **写剧本与 spoilerGates 脱节** | ② truth 定义了 forbiddenFacts，⑥ 生成时 LLM 仍写入等价语义 |
| **真凶 POV 天然冲突** | 模型倾向写「完整内心戏」→ 动机/手法/时间线自曝 |
| **evaluate 不稳定** | 第一代漏检真凶 ch1；第三代误报 ch1 走私 |
| **deAi / sanitize 二次改写** | 可能保留或重新引入 forbidden 语义 |

### 4.2 公平推理（fairness = 6）

| 根因 | 说明 |
|------|------|
| **独家目击** | 暗格、细线、油布包、走私笔记本等仅一人剧本出现 |
| **矩阵与正文双轨** | rows.newClueIds / forbidden 与正文不同步（遗嘱涂改、细线时机） |
| **12 格串行但无硬约束** | peerScriptDigest 是软约束，无法阻止「新发明独占细节」 |

### 4.3 结构与入库

| 根因 | 说明 |
|------|------|
| truth 逻辑 | 第一代自杀+他杀并存（v2/v3 已修） |
| killer 字段格式 | 第一代非 role-N（v2/v3 已修） |
| 矩阵↔剧本 | 第三代细线/走私 notebook 分配混乱 → importReady 6 |

## 10. 第四代架构转向（v4 — innocent-inject + 机械门禁）

> **结论升级**：Gen1–Gen3 证明问题不在 prompt 内卷，而在 LLM「扮演想隐瞒的凶手」的能力边界。sanitize rewrite 让同一模型检查并重写自己的输出，无法提供「刻意隐瞒」的元认知。

### 10.1 策略转向

| 旧模式 | 新模式（v4） |
|--------|----------------|
| LLM 扮演真凶 + 防守性 prompt | **innocent_witness**：LLM 扮演无辜者写 alibi |
| LLM sanitize 删剧透 | **规则注入破绽**（hedge 否认句 + 肢体语言 tell） |
| 全部生成完再 evaluate | **每格生成后三道机械门禁**，未通过则重试 innocent 通道 |
| killer deAi / sanitize | 真凶 ch1/ch2 **跳过 deAi/sanitize** |

### 10.2 已实现模块（代码）

| 模块 | 路径 | 职责 |
|------|------|------|
| innocent 通道 prompt | `matrix-player-script.js` → `buildMatrixInnocentKillerScriptMessages` | 明确「你不是凶手」 |
| 规则注入 | `pipeline-matrix-killer-innocent.js` | `injectKillerContradictions` |
| 质量门禁 | `pipeline-matrix-script-gates.js` | forbiddenFacts / 未授权物证 / guilt 计数 |
| 编排 | `pipeline-matrix-deepseek.js` | 默认 `killerScriptMode !== "legacy"` 时走 innocent 通道 |

### 10.3 三道门禁（每格剧本生成后立即执行）

1. **forbiddenFacts 扫描** — 所有角色
2. **物证发现授权** — `host_confirm` 线索仅当 `newClueIds` 或 `auto` 线索已授权；违规句替换为「光线太暗看不清」
3. **guilt 陈述计数**（innocent 真凶）— 超过 2 处罪恶感/认罪表述 → 整格 innocent 剧本重新生成（最多 2 次）

### 10.4 预期效果（待 Gen4 生成验证）

| 维度 | Gen3 | Gen4 目标 |
|------|------|-----------|
| spoilerSafety | 5 | **8+**（真凶 ch1/ch2 无内心认罪） |
| fairness | 6 | **7.5+**（未授权发现被机械删除） |
| overall | 6.5 | **7.5+** |

验证命令：`npm run generate:matrix-pilot`（`promptVersion: matrix-v5-structured-log`）

## 12. v4 失败判定与 v5 范式（已实现）

**v4 根本错误**：假设 LLM 能写「完整无辜叙事」；实际仍会补全冲突与辩解（旋转开关句），并发生 persona 上下文污染（苏晴串台）。

**v5 默认策略** — 步骤⑥拆为三通道、机械缝合：

| 通道 | 实现 |
|------|------|
| 客观行动日志 | `buildActionLogMessages` → `stripPsychologyFromAction` |
| 规定情感/疑惑 | `fillFeelingPack`（无 LLM） |
| 公聊与观察 | `buildDialogueLogMessages`（独立调用，与行动隔离） |

代码：`pipeline-matrix-structured-script.js`、`prompts/matrix-structured-script.js`
每格 script 含 `structured: { actionLog, feelingsPack, dialogueLog }`。
