# 《未归还》完整剧情包 V2

> 状态：`complete_package_review`。这是从可试玩原型扩展出的完整主持与角色包，仍需真人桌测后才能标记为正式发行稿。

## 这套包解决什么

四名玩家不是寻找凶手，而是在午夜前处理一份已经持续二十五年的公共记忆债务：一箱被写成“洪损未回收”的工人口述史重新出现，旧馆、新馆、基金、影片和两个家庭都必须决定，事实怎样被核验、材料怎样回归、哪些内容可以对外传播。

## 阅读顺序

### 作者与审核者

1. `00-剧情合理性审查.md`
2. `story-contract.json`
3. `narrative/00-叙事总设计.md`
4. `narrative/01-共同事件与交叉矩阵.md`
5. `narrative/03-四线交叉剧情图谱.md`
6. `maps/00-全剧情流程图谱.md`

### 主持人

1. `host/00-主持总册.md`
2. `host/01-逐幕流程与朗读.md`
3. `host/02-事实核验与结局.md`
4. `host/03-完整真相与复盘.md`
5. `host/04-桌面工具卡.md`

### 玩家

每人只阅读自己角色目录，并严格按 `00 → 01 → 02 → 03` 分幕开启。每一幕先读 `narrative/` 中自己的同号正文，再读 `roles/` 中自己的同号行动页；线索卡由主持按幕次单独发放。

## 目录

- `narrative/`：四名角色的分幕长篇正文，共 16 份；另含叙事总设计、共同事件矩阵、防串词边界和四线剧情图谱。
- `roles/`：四名角色的开场身份、秘密边界与三幕行动资料，共 16 份。
- `clues/`：E01–E12 十二张独立线索卡，不再组合成证据包。
- `host/`：开场、场控、核验、结算和完整复盘。
- `maps/`：剧情流程、事实证据、角色关系与结局分流图谱。
- `story-contract.json`：机械测试和后续产品导入使用的唯一结构合同。
- `START-HERE.md`：打印、装袋与开桌入口。
- `review/FINAL-REVIEW.md`：机制包的机械与 DeepSeek 终审结论。
- `review/NARRATIVE-REVIEW.md`：长篇正文的两轮盲读、修订记录与真人桌观测线。

## 不可混用

`prototype-v1/` 是历史测试基线；`complete-package/` 是扩写后的完整包。真人开桌时只能选一套，不能把两套角色页或线索页混发。
