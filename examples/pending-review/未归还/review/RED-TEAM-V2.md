# DeepSeek 红队 V2

模型：`deepseek-v4-flash`
结论：`revise_then_prototype`

## 识别出的有效问题

- 十二份来源若逐份展示，第二幕会信息过载。
- 需要明确证据的独立来源，避免“同一个人写两份材料”形成伪交叉。
- 第 9.3 条若第三幕才出现，会像为修复性结局临时创造的后门。
- 需要写清冲突行动如何结算，避免多个结局同时满足。
- F5 必须由今夜正在使用旧叙事的材料直接支持，而不能只依靠前人的纠正信。

## 已修复

- 保留十二个来源，但整理为八个桌面证据包，第二幕只处理四包。
- 每个来源增加 `sourceGroup`，合同测试会拒绝同源双证据。
- 第 9.3 条改为标准“重大陈述错误补救条款”，随开场签约包出现。
- F5 改由完整录音的剪辑记录与今夜签约包交叉验证，纠正信仅加强。
- 新增固定结算顺序：立即公开 → 更正后开馆 → 照常开馆 → 未能交接。
- “未能交接”成为所有不完整组合的默认结果，保证拒绝合作仍能产生可信结局。

## 未采纳建议

红队建议在某个角色拒绝时允许其他玩家代行其终局权力。未采纳，理由是：

- 独占权力是玩家角色不可替代性的核心；
- 拒绝合作应当真实关闭最优修复路径；
- 系统绕过拒绝，会让角色选择失去代价。

处理方式不是“补一个替代签字人”，而是确保其余玩家仍能验证部分事实，并进入 A、C 或 D 结局。

## 进入原型前仍需人工核对

- 八个证据包能否在 75 分钟主体时间内读完并讨论。
- P02 的照片序列是否足以表现何岚的组织行为，而非只证明她在场。
- P08 的项目章能否清楚证明公共材料属性。
- 即使没有最佳 B 结局，玩家是否会觉得 A、C、D 都是自己造成的，而不是系统惩罚。
