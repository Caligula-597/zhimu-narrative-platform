# 织幕三端产品功能总览与完整创作流程

> 文档定位：以当前仓库前端实现为准的详尽产品说明、页面导航说明和验收基线。
> 适用对象：剧本开发者、产品经理、交互设计、前后端研发、测试与运营。
> 当前版本：2026-07-16。
> 说明：本文区分“当前已经实现的表现”与“首次使用者评审后的优化建议”，不把规划功能描述成已上线功能。
> 工程状态：架构计数、专项矩阵、发布证据与剩余非功能风险以 [PROJECT_STATUS.md](./PROJECT_STATUS.md) 为准。

## 1. 产品由哪三端组成

织幕围绕同一个“世界模板”和多个“运行房实例”，提供三个相互协作但权限不同的前端。

| 端 | 面向谁 | 主要任务 | 核心数据范围 |
|---|---|---|---|
| 创作者端 | 作者、编辑、世界拥有者 | 写世界、真相、角色、私人剧本、场景、线索、规则，创建测试房并复盘改本 | 世界模板为主，也可选择一个运行房观察测试数据 |
| Host 主持端 | 主持人、导演 | 选世界和运行房、邀请玩家、监控进度、确认规则事件、手动干预、存档和生成本场报告 | 单个运行房的实时状态 |
| Play 玩家端 | 玩家或游客 | 找房/输邀请码、选角、阅读私人剧情、探索、获得和分享线索、投票、私密行动、语音、复盘 | 当前玩家在当前运行房中有权看到的内容 |

核心产品边界：

- 世界模板保存可复用的创作内容，例如章节、角色、分幕、场景、线索、Segment 和规则。
- 运行房保存一场实际游戏的数据，例如玩家席位、阅读进度、调查记录、线索归属、投票、主持待确认事件、语音房、存档和复盘。
- 同一个世界可以创建多个平行运行房，各房间互不共享玩家进度。
- 三端不直接共享浏览器状态；它们通过同一套 API、事件契约和房间事件流保持一致。

## 2. 创作者端的信息架构

当前创作者端同时提供两层导航。

### 2.1 流程层：创作驾驶舱的六个阶段

创作驾驶舱用于回答“我现在写到哪一步、下一步该做什么”。页面表现为：

- 顶部：六阶段标签和各阶段完成百分比。
- 左栏：当前阶段检查项。
- 中栏：当前阶段的核心画布或快速编辑区。
- 右栏：内容副窗、系统建议、结构识别和 AI 续写入口。
- 顶部操作：刷新数据、系统检查、测试房。

六阶段如下：

| 阶段 | 当前检查项 | 专业编辑深链 |
|---|---|---|
| 1. 灵魂的种子 | 灵感卡、一句话梗概、核心卖点、商业定位 | 世界设置、内容副窗 |
| 2. 骨架的搭建 | 真相链、关系网、章节结构、线索 | 真相与关系、编排图谱、线索管理 |
| 3. 血肉的填充 | 角色与分幕、发布节奏、真相伏笔、玩家视角 | 角色私人剧本、真相与关系、玩家预览 |
| 4. 游戏的规则 | Segment、线索分发、自动化规则、主持预演 | Segment 工作台、线索管理、规则页、Host |
| 5. 肌肤的裁剪 | 内容生产、主持 runbook、线索与场景、导入导出 | Writer、Segment、Studio、导出流程 |
| 6. 测试与发布 | 测试运行房、跑局数据、系统检查 | 运行房管理、Host、复盘改本 |

### 2.2 工作模式层（原「六大工作区」）

工作模式回答“我要做哪一类工作”，**不是第二套创作顺序**。日常以驾驶舱六阶段为主流程。

| 工作模式 | 用途 | 主要入口 |
|---|---|---|
| 创作驾驶舱 | 看全局完成度、风险和深链 | 六阶段流程 |
| 内容生产 | AI、母稿、私人分幕、导入导出 | AI 剧本创作、完整剧情、Writer、内容包 |
| 结构编排 | 把章节、私人分幕、线索和主持 runbook 聚合成运行段落 | Segment 工作台、Studio、Clues、Rules |
| 真相与关系 | 管理核诡、断言、时间线、伏笔、关系图 | Story Bible 五个 Tab |
| 测试与发布 | 发布检查、质量报告、玩家/主持视角试跑 | 发布检查、测试房、Play、Host |
| 复盘改本 | 用真实跑局数据返回创作环节 | 分幕完成率、线索命中率、运行分析 |

### 2.3 左侧「精细编辑器」导航

侧栏主流程为「创作驾驶舱」；「精细编辑器」展开后进入专业页：

- 角色私人剧本
- 真相与关系
- 剧情编排图谱
- 线索管理
- 自动化规则
- 小游戏设计
- 存档与复盘
- 账号与资产
- 世界设置
- 运营

这些页面是精细修改区，不是另一套创作顺序。流程层负责告诉用户该做什么，专业页负责真正编辑复杂内容。

## 3. 从零创建世界的完整流程

### 3.1 前置步骤：登录、选择或创建世界

用户进入创作者端后：

1. 登录或注册账号。
2. 世界切换器读取有权限访问的世界。
3. 已有世界可直接打开；没有世界时点击“创建新世界”。
4. 当前世界 ID、运行房 ID 和最近工作区会由运行时状态协调器保存。
5. 顶部世界切换器显示世界名和公共章节数量；加载失败时区分登录失效、无权限、后端不可达和内容为空。

### 3.2 五步创建向导

#### 第一步：创建方式

填写：

- 世界名称。
- 一句话简介。
- 运行模式：剧本杀房间、跑团房间或混合长线房间。

当前表现：三张大卡片选择模式。模式会影响角色字段文案、首章字段文案和初始化设置。

#### 第二步：角色与席位

席位列表显示角色头像首字、角色名、目标和编辑按钮。可新增、编辑或删除角色。

每个角色填写：

- 角色名称。
- 个人任务 / 探索方向 / 长期目标，名称随运行模式变化。
- 公开身份：其他人或公共资料可以看到的角色介绍。
- 角色秘密 / 背景钩子 / 隐藏支线：该角色私人内容的基础。
- 剧本杀模式可上传 TXT 或 Markdown 专属剧本文档。
- 角色剧本正文：导入后仍可修改。

约束与表现：

- 至少保留一个角色席位。
- 角色编辑在向导内切换成独立编辑页，不离开向导。
- 公共身份、私人档案和角色正文分开保存到向导草稿。

#### 第三步：章节与内容

选择内容来源：

- 导入剧情文档。
- 使用标准模板。
- 从空白世界开始。

填写：

- 首章名称 / 首场冒险名称 / 首个阶段名称。
- 角色序章标题 / 开场钩子名称 / 个人节点标题。
- 角色序章正文 / 开放探索引导 / 阶段私人剧情。

剧本杀模式还会列出每个角色的专属文档是否已经导入。

#### 第四步：自动化规则

可启用四类模板：

- 阅读完成后解锁下一幕。
- 核心线索满足后开放新场景。
- 章节结束后由主持确认进入下一章。
- 卡关时发送弱提示。

每张模板卡显示“检测条件、执行动作、自动或主持确认模式”。点击卡片切换启用状态。

#### 第五步：测试并发布

向导展示即将写入的内容：

- 一个世界。
- 一个起始章节。
- 所有角色席位。
- 每个角色的一段私人剧情。
- 已选择的起始规则。
- 一个测试运行房。
- 一个公共语音房。

点击“创建测试房间”后，数据真实写入云端，当前世界和房间自动切换到新记录，随后跳转到“自动化规则”页面。完成弹窗展示邀请码和已创建规则数量。

## 4. 创作者端的推荐生产流程

向导只负责搭骨架。正式开发建议按以下顺序推进。

### 4.1 阶段一：立项与商业定位

在“创作驾驶舱 → 灵魂的种子”中完成：

- 灵感卡：记录零散点子，可填入梗概或删除。
- 一句话梗概：明确主角、目标、阻碍和悬念。
- 核心卖点：玩家为什么愿意玩、与同类剧本有什么差异。
- 商业定位：目标玩家、玩家人数、时长、类型、题材和世界设置。

需要精细修改时跳转：

- 世界名称、摘要和运行设置 → “世界设置”。
- AI 扩写和结构识别 → 右侧内容副窗或“AI 剧本创作”。

### 4.2 阶段二：真相、关系和案件时间线

进入“真相与关系”，页面采用五个 Tab。

#### 真相链

填写：

- 断言标题。
- 断言内容。
- 可信度：canon、inferred、misdirection、unknown。

表现：断言以卡片列表展示，可删除；供主持 runbook 和复盘引用。

#### 核诡

填写：

- 核心概要。
- 凶手角色。
- 手法。
- 动机。
- 受害者。
- 主持备注。

#### 案件时间线

填写：

- 时间标签，例如 22:15。
- 事件概要。
- 不在场或目击备注。

#### 伏笔

填写：

- 伏笔标题。
- 埋设说明。
- 表面含义。
- 真实含义。
- 回收说明。

#### 关系网

填写：

- 起点角色。
- 终点角色。
- 关系标签。
- 关系强度由相关专业入口支持时可保存。

表现：上方关系图，下方关系记录和新增表单。

### 4.3 阶段三：内容生产

“内容生产”是入口聚合页，提供六项操作。

#### AI 剧本创作

AI 向导当前表现为左侧步骤梯、右侧分层编辑器、底部导入操作。完整瀑布流为：

1. 立项。
2. 真相。
3. 角色。
4. 信息矩阵。
5. 主持手册。
6. 逐幕剧本。
7. 评判。
8. 机械入库。

立项需要填写：

- 主题。
- 玩家人数，限制 4～8。
- 章节数量，限制 3～5。
- 每章目标字数，限制 2000～12000。
- Matrix 模式：本格或变格。
- 时代预设。
- 体量档位：示范、标准、完整。
- 玩家本视角：第二人称或第一人称。
- 额外矛盾冲突。
- 场景基调。
- 文风锚点，建议提供 2～3 段范例。
- 禁用词或套话，每行一条。
- 剧情纲要正文。
- 人物关系草图。
- 真相概要。
- 误导线草图。

各层生成结果先作为本地草稿显示，不直接写入世界。用户可以逐层重试、修改、应用评判提示，最后选择：

- 仅上传编排。
- 上传全部到云端。
- 保存或读取本地草稿。

机械入库会把确认后的内容映射为世界、章节、角色、私人分幕、场景、线索、调查点、Segment、规则和主持运行信息。

#### 完整剧情

用于维护整本母稿和章节总览。支持：

- 手动修改完整母稿。
- 从图谱同步到母稿。
- 从母稿同步到图谱。
- 同步后继续进入 Writer 或 Studio 精修。

#### 导入内容

支持：

- Word、TXT、Markdown 文档解析。
- PDF/图片按页导入角色剧本。
- JSON 内容包预览并追加导入。
- 导入前展示角色、章节、线索数量、引用问题和重名提示。

导入不会静默覆盖已有内容；内容包使用 ID 重映射和来源键去重。

#### 角色私人剧本

进入 Writer 专业页。页面由角色档案、角色私人剧本、章节发布控制、发布检查和创作版本组成。

角色席位填写：

- 角色名称。
- 公开身份。
- 角色秘密。
- 席位顺序。

角色档案与私人分幕分开：角色档案用于外在目标、秘密和人物弧光；分幕用于实际发给玩家阅读的正文。

私人分幕编辑器填写：

- 分幕标题。
- Markdown 正文。
- 所属公共章节。
- 发布状态：草稿、测试中、已发布。
- 查找关键词和替换内容。

表现：

- 每个角色是可折叠卡片。
- 卡片内按顺序列出分幕摘要和发布状态。
- 编辑分幕时进入大尺寸正文编辑器，顶部显示角色、序号、字数和保存状态。
- 支持保存并关闭；已有分幕支持编辑，空角色支持新增第一幕。

章节发布控制填写：

- 章节名称。
- 章节摘要。
- 发布阶段。
- 解锁方式：主持确认、规则自动、仅手动。

精细修改跳转：

- 角色秘密和分幕正文 → Writer。
- 公共章节环境、场景归属和图谱位置 → Studio。
- 真相和人物关系 → 真相与关系。
- 运行段落和主持手册 → Segment 工作台。

#### 导出交付包

第一步选择交付物：

- 内容包 JSON。
- 按角色拆分的玩家剧本 Markdown。
- 线索清单 Markdown。
- 主持手册 Markdown。
- 同时保存创作版本快照。

第二步确认世界名称和导出范围后生成文件。

#### 剧情结构提取

用户在独立工作台粘贴剧情梗概、母稿片段或搜证流程。推荐用“场景：”“调查点：”“线索：”分段，系统先展示场景、调查点、线索、建议连线和整理建议；修改原文会立即让旧预览失效，重新提取并复核后需要二次确认才会追加到剧情编排。

该功能只追加场景、调查点、线索和剧情连线，不创建章节、角色、私人分幕或自动化规则，也不会覆盖已有节点。请求固定绑定打开工作台时的剧本；若写入成功但页面刷新失败，应手动刷新确认结果，不能重复导入。

### 4.4 阶段四：Segment 结构编排

Segment 是运行段落的聚合层，不替代章节或私人分幕。页面为三栏：

- 左栏：Segment 列表、从章节同步、刷新、创建段落。
- 中栏：段落编辑器。
- 右栏：关联资源和专业页跳转。

创建 Segment 填写：

- 段落键，例如 ch1。
- 标题。

编辑 Segment 填写：

- 标题。
- 顺序。
- 本幕目标。
- 玩家可读内容摘要。
- DM 任务。
- 可开放线索或地图。
- 私聊建议。
- 预计时长。
- 推进条件。
- story 扩展 JSON。
- 主持流程 flow。
- 主持真相 hostTruth。
- 应发线索 clueGrants，格式为“线索 ID | 发放时机 | 角色键”。
- 补救话术 fallbacks，每行一条。
- operations 高级 JSON。

关联资源支持：

- 公共章节。
- 私人分幕。
- 场景。
- 线索。
- 物品。
- 规则。
- 真相断言。

右栏可直接跳转到 Studio、线索库和规则页继续精修。

### 4.5 阶段五：剧情编排图谱

Studio 用可视化画布组织章节、场景、线索、物品和调查点。

页面表现：

- 顶部工具栏：新增节点、自动排布、折叠/展开场景、缩放。
- 中间画布：节点卡片、连接点、连线和拖拽位置。
- 筛选：按节点类型控制可见内容。
- 右侧编辑区：选中节点后显示对应字段。
- 节点可建立主线、并列或延伸关系。

公共章节填写：

- 章节名称。
- 章节摘要。
- 公共环境 publicEnvironment。
- Matrix 幕键。
- 复盘公开摘要。

场景填写：

- 场景标题。
- 场景摘要。
- 复盘公开摘要。
- 场景正文或描述。
- 开放状态：锁定或初始开放。
- 所属章节。
- 可见角色范围。
- 主持备注。

线索填写：

- 线索标题。
- 线索正文。
- 发放模式：自动、主持确认、探索获得。
- 类型：文字、图片、文件、音频。
- 关联资产。
- 默认可见性：角色私密、房间公开、主持可见。
- 重要程度：普通、关键、烟雾弹。
- 解锁说明或面包屑。
- 主持提示。

物品填写：

- 物品名称。
- 物品描述。
- 是否唯一。
- 是否可消耗。
- 关联资产。
- 主持备注。

调查点填写：

- 调查点标题。
- 调查描述。
- 所属场景。
- 调查结果。
- 成功后发放线索。
- 所需物品。
- 是否需要主持确认。
- 是否一次性。
- 主持备注。

图谱精细操作：

- 拖拽节点并持久化坐标。
- 添加、移动或删除连接点。
- 从连接点拖到另一个节点创建连线。
- 自动排布多个节点。
- 删除节点前查看引用影响。

### 4.6 阶段六：线索、规则和小游戏

#### 线索管理

用于线索列表、搜索、筛选、批量操作和精细编辑。线索的正文、发放模式、资产、重要程度和主持提示与 Studio 使用同一条数据记录。

#### 自动化规则

列表卡片显示：

- 启用或暂停状态。
- 规则名称。
- 自动、主持确认或手动模式。
- “当……则……”摘要。
- 剧情目的。
- 优先级。
- 世界模板或绑定房间。

编辑器提供可视化和 JSON 两个 Tab。基础字段：

- 规则名称。
- 绑定范围。
- 触发模式。
- 剧情目的。
- 优先级。
- 是否启用。
- 检测条件。
- 执行动作。

保存前会执行结构和引用校验。复杂的 any/not 结构可切换到 JSON。

#### 小游戏设计

当前主要支持数字锁模板。填写标题、玩家提示、答案和尝试次数等模板字段后，可：

- 保存到当前世界。
- 在当前运行房测试启动。
- 从 Host 端观察同步状态。
- 在 Play 端提交答案并看到剩余次数或完成状态。

## 5. 测试与发布流程

### 5.1 发布检查

“测试与发布”页提供：

- 运行发布检查。
- 查看阻塞项和警告项。
- 将当前检查结果存档为质量报告。
- 创建或管理测试运行房。

检查结果会提供跳转目标，用户可直接进入角色、分幕、线索、规则或编排页面处理。

### 5.2 视角模拟

提供三种入口：

- 玩家阅读模拟：不要求真实玩家入房，以 Player 初始查询规则展示角色公开信息、角色秘密、当前可读私人分幕，以及场景、线索和隐藏原因；可切换角色、测试/正式房阶段与章节筛选。
- 独立 Play 玩家端：用真实运行房和玩家身份验收完整流程。
- 独立 Host 主持端：验收实时监控、待确认和手动干预。

模拟页不会伪造运行中状态：非首幕、场景和线索分别依赖运行时解锁、获取或分享记录。选择真实运行房时仅借用房间阶段推演初始态，并提供跳转真实 Player 的核验入口；它不会把创作 metadata 或线索 `visibility=public` 误报为玩家已经获得的内容。

### 5.3 创建和管理运行房

创建房间填写：

- 房间名称。
- 邀请码由界面生成或提交。
- 是否公开到玩家大厅。

房间列表显示：

- 房间名称。
- 邀请码。
- 已选角玩家数和角色席位数。
- 房间状态。
- 是否公开。
- 邀请玩家、复制链接、切换房间、公开/取消公开操作。

### 6.1 进入房间

1. 主持登录。
2. 选择有主持权限的世界。
3. 选择已有运行房，或创建测试房。
4. 页面顶部显示当前房间。

- 刷新房间状态。

- 创建存档点。

### 6.5 运行辅助

主持页面还包含：

- 小游戏控制。
- 节奏计时器。
- 玩家等待条。
- 玩家实时动态。
- 主持审计。
- 公共环境与分幕播报参考。
- 线索掌握矩阵。
- 本场运行报告。
- 存档恢复和跨房复盘入口。

## 7. Play 玩家端完整流程

### 7.1 入房和选角

玩家可以：

- 从公开大厅选择房间。
- 输入邀请码读取房间和角色席位。
- 查看角色是否已被占用。
- 选择空闲角色进入房间。
- 已绑定角色的玩家重新进入时回到原席位。

### 7.2 局中五个主 Tab

| 主 Tab | 包含内容 | 当前表现 |
|---|---|---|
| 现在 | 当前目标、主持等待提示、语音和成员概况 | 首页卡片、提醒条、小游戏区域 |
| 剧情 | 当前角色和私人分幕 | 角色私人档案、分幕列表、完成进度 |
| 调查 | 探索、线索、背包 | 开放场景、调查点、线索分享、物品 |
| 博弈 | 任务与口供、怀疑、投票/私密行动 | 表单、状态卡和主持反馈 |
| 复盘 | 复盘、时间线、个人笔记 | 运行结果、可见事件和私人推理 |

有新内容时，Tab 显示脉冲点或“+N”徽标。

### 7.3 私人剧情

玩家只看到当前角色有权读取的分幕。每段显示标题、正文和状态；玩家主动点击完成后记录阅读进度，并可能触发规则。

### 7.4 调查和线索

玩家可以：

- 查看已经开放的场景。
- 执行有权限的调查点。
- 满足物品或角色条件后取得结果。
- 获得个人线索。
- 标记线索已读。
- 将线索公开给全房间。
- 私享给指定角色。
- 写玩家解读。

背包显示已获得物品、数量以及是否可消耗。

### 7.5 博弈和社交

玩家可以：

- 查看并完成本幕任务。
- 提交口供。
- 记录对其他角色的私人怀疑和理由。
- 参与投票或指认。
- 提交私密行动、秘密交易或向主持提问。

### 7.6 语音和复盘

- 公共语音房对所有房间成员可见。
- 私密语音房仅对受邀成员可见。
- 语音文字消息实时刷新。
- 复盘区展示本局结论、揭示轨迹、时间线和满意度反馈。

## 8. 三端如何统一同步

### 8.1 写入链路

一次影响运行房的操作遵循：

1. 创作者、Host 或 Play 调用统一 API Client。
2. Backend 在数据库事务中写业务数据。
3. 同一事务写入事件 Outbox。
4. 事务提交后，Dispatcher 将事件写入 Journal 并发送 PostgreSQL 通知。
5. Room SSE 将事件推给当前房间连接。
6. 三端使用同一份 Room Event JSON Schema 校验事件类型和必填字段。
7. 各端按自身权限和页面职责做局部刷新、徽标、Toast 或列表更新。

这保证了“业务写入成功但事件丢失”的概率显著降低；通知失败不会要求重新执行已提交的业务动作。

### 8.2 断线和恢复

- SSE 使用事件游标和 Journal 重放断线期间的事件。
- 客户端重连后执行一次 reconcile，以 API 最新快照纠正局部状态。
- Host 和 Play 在 SSE 断开时使用约 15 秒轮询兜底。
- 主创作者端在选择运行房时也监听房间事件；没有运行房时只加载世界模板数据。
- 未注册事件或缺少必填字段的事件会被客户端契约层拒绝，不直接污染 UI 状态。

### 8.3 关键事件在三端的表现

| 事件 | 创作者端 | Host 端 | Play 端 |
|---|---|---|---|
| 玩家加入/被踢 | 刷新运行房和玩家统计 | 玩家表状态变化 | 被踢玩家退出局中页 |
| 分幕完成 | 总览/运行数据刷新 | 玩家完成进度和动态刷新 | 当前玩家进度刷新 |
| 分幕解锁 | 运行状态刷新 | 玩家详情刷新 | “剧情”Tab 脉冲并提示新分幕 |
| 场景开放 | 图谱模板不被改写，只刷新运行状态 | 当前房间开放状态刷新 | “调查”Tab 脉冲并提示新场景 |
| 发放线索 | 测试数据和复盘统计刷新 | 线索矩阵刷新 | “调查”Tab 脉冲，显示获得/公开/私享提示 |
| 发放物品 | 运行状态刷新 | 玩家详情刷新 | 背包脉冲并提示物品名称 |
| 调查完成 | 运行数据刷新 | 动态、玩家详情和待确认刷新 | 调查区域刷新并提示完成 |
| 主持待确认 | 通知数量和运行状态刷新 | 待确认队列出现卡片 | 显示“等待主持确认” |
| 主持确认/拒绝 | 通知数量刷新 | 队列状态变化并写审计 | 刷新剧情、调查和线索，显示处理结果 |
| 主持提醒 | 运行动态刷新 | 写入日志和审计 | 首页提示条和 Toast |
| 小游戏开始/更新/完成 | 测试状态可观察 | 小游戏控制卡更新 | 首页机关区域更新、显示剩余次数或完成结果 |
| 存档恢复 | 创作者复盘数据刷新 | 房间全量刷新和审计 | 玩家首页全量 reconcile |
| 语音文字消息 | 房间动态可见 | 动态刷新 | 当前语音房直接刷新，否则语音徽标提示 |

### 8.4 世界模板同步与房间同步的区别

- 修改角色、章节、分幕、线索模板、场景模板或规则时，通过普通 API 和世界 `content_revision` 控制并发写入。
- 运行时的解锁、发放、阅读、调查和投票通过 Room Event 同步。
- 修改模板不会自动覆盖已经产生的房间进度。
- Host 的手动操作只影响选中的房间，不应反向改写世界模板。

## 9. 首次使用者视角评审

以下评审假设我是第一次打开织幕、准备开发一部六人本格剧本的作者。

### 9.1 第一印象

产品能力已经覆盖从立项、结构、角色、规则、试跑到复盘的完整闭环，专业深度明显高于普通在线文档工具。尤其是角色私人分幕、真相 Bible、Segment runbook、Host 监控和 Play 运行态之间已经建立真实数据关系。

最大的障碍不是缺功能，而是同一个创作对象在多个页面出现，首次用户不容易判断“哪个页面才是最终来源”。

### 9.2 必须优先修正的问题

#### P0：六阶段和六大工作区概念重叠 — **已落地（UI 文案）**

当前用户会同时看到：

- 六阶段：灵魂、骨架、血肉、规则、裁剪、发布。
- 六工作区：驾驶舱、内容生产、结构编排、真相、发布、复盘。
- 左侧专业工具：Writer、Truth、Studio、Clues、Rules 等。

首次用户可能误以为需要走三遍流程。

已落实：

- 侧栏分组改为「主流程」；展开项文案为「精细编辑器」。
- 工作区 Hub 改称「工作模式」，并写明非第二套顺序。
- 驾驶舱 Hero 标明六阶段为唯一主流程。
- 仍待：每个阶段只显示一个主按钮和不超过三个深链（结构压缩，另批）。

#### P0：AI 步骤文案不一致 — **已落地**

已统一为八层文案（去掉「五步向导」误导）：

“八层生成流程：立项 → 真相 → 角色 → 信息矩阵 → 主持手册 → 逐幕剧本 → 评判 → 入库。”

启动区显示预计调用/耗时说明（`PIPELINE_FLOW_ESTIMATE`）。

#### P0：内容来源层级需要明确 — **已落地（UI 说明）**

当前存在母稿、章节、私人分幕、Segment、Studio 节点、真相断言和主持 operations。它们不是重复数据，但首次用户看不出边界。

已在驾驶舱、Writer、内容生产与结构编排页固定「内容层级」可展开图：

1. 母稿：完整叙事原文。
2. 章节：公共剧情阶段。
3. 私人分幕：发给单个玩家阅读的正文。
4. Studio 节点：可探索的场景、线索、物品和调查点。
5. Segment：把上述资源聚合为可主持的一幕。
6. Rule：定义这一幕如何自动推进。

#### P0：发布状态缺少统一总开关 — **已落地（影响预览）**

章节和分幕有 draft/testing/published，场景又有 openStatus，房间还有 testing/运行状态。作者很难判断“现在玩家到底能看到什么”。

已增加「发布影响预览」与「玩家阅读模拟」：选择角色与房间类型（假设测试房/正式房或真实运行房），列出章节、私人分幕、场景、线索、任务的初始可见性与不可见原因。共享投影规则已经与 Player 查询对齐：首幕按自身发布状态进入阅读列表，非首幕与场景依赖运行时解锁，线索依赖获取或分享记录；真实运行进度仍须进入独立 Player 验收。

### 9.3 高优先级体验修正

#### P1：Segment 表单暴露过多工程术语

`beatPlan`、`operations`、`clueGrants`、`refType/refId` 对剧本作者不友好。

建议默认使用中文业务名称：

- 本幕流程。
- 主持行动清单。
- 发放线索计划。
- 关联内容。
- 卡关补救。

JSON 和 ID 只放在“高级设置”。线索关联应使用可搜索下拉选择，而不是要求填写线索 ID。

#### P1：角色档案与角色秘密入口需要合并感知

当前角色席位、角色档案、私人分幕是合理的数据拆分，但页面上容易被理解成三套角色资料。

建议每个角色使用统一详情页，内部三个 Tab：

- 对外身份。
- 作者档案。
- 玩家分幕。

保存后返回角色列表，并在卡片上显示三个区域的完成度。

#### P1：专业页之间缺少固定面包屑

从驾驶舱进入 Studio，再进入 Clues 或 Writer 后，用户不容易回到原阶段。

建议所有专业页顶部固定显示：

`创作驾驶舱 / 骨架的搭建 / 线索管理`

并提供“保存并返回阶段”。

#### P1：三端同步状态需要更可见

目前 Host 能看到实时连接风险，Play 有内部状态，但创作者端缺少统一同步诊断。

建议三端统一显示：

- 实时已连接。
- 正在重连。
- 轮询兜底。
- 最后同步时间。
- 手动重新同步。

断线时不要只依赖 Toast，应在页面顶部持续显示状态条。

#### P1：版本快照需要准确说明恢复范围

当前内容版本主要恢复章节和私人分幕，并不是完整世界回滚。

建议按钮改名为“保存章节与分幕版本”，或扩展快照恢复范围到场景、线索、Segment、规则和真相 Bible。恢复前必须展示差异和影响范围。

#### P1：测试流程应变成强引导

目前创建房间、打开 Host、打开 Play、运行检查分别存在，但需要作者自己理解顺序。

建议新增“一键进入测试流程”：

1. 运行发布检查。
2. 创建隔离测试房。
3. 复制玩家链接或创建测试玩家。
4. 左右并排打开 Host 和 Play。
5. 执行预设验收脚本。
6. 结束后生成运行报告并回到复盘改本。

### 9.4 中优先级修正

#### P2：创建模式承诺需要收敛

向导提供剧本杀、跑团和混合模式，但底层初始化仍主要创建世界、章节、角色、分幕、规则和房间这一套结构。

建议在跑团和混合模式能力完全差异化前，明确标注“模板偏好”，避免用户理解为三个完全不同的运行引擎。

#### P2：字段默认值和示例不足

核诡、伏笔、规则、调查点等字段应提供一个可切换的完整示例，而不仅是占位符。示例需要能直接形成一条“调查 → 线索 → 主持确认 → 新场景”的闭环。

#### P2：复盘数据需要直接生成修改任务

当前完成率和命中率可以跳回专业页，但仍需作者自行定位问题。

建议自动生成：

- 低完成分幕修改任务。
- 从未获得的关键线索检查任务。
- 高频卡关 Segment 的补救话术任务。
- 主持手动干预过多的规则优化任务。

## 10. 建议收敛后的七步主流程

建议最终把用户心智收敛成七步：

1. 立项：一句话梗概、玩家、时长、类型。
2. 真相：核诡、时间线、关系和伏笔。
3. 内容：公共章节、角色档案和私人分幕。
4. 互动：场景、调查点、线索和物品。
5. 运行：Segment、主持 runbook 和自动化规则。
6. 测试：创建隔离房，Host/Play 并排试跑。
7. 发布与复盘：发布影响预览、质量报告、运行数据改本。

每一步只保留：

- 一个当前目标。
- 一组必填字段。
- 一个主要编辑器。
- 一个“下一步”按钮。
- 一个“高级工具”入口。

## 11. 产品和验收使用方式

产品经理使用本文检查：

- 页面是否有明确入口、返回路径和下一步。
- 同一字段是否在多个页面出现但含义不一致。
- 当前表现和规划表现是否被混写。

研发使用本文检查：

- 创作者写入是否修改世界模板还是运行房。
- 运行时操作是否通过 Outbox 和 Room Event 同步。
- 三端是否消费同一事件契约。
- 页面局部刷新是否同时有断线 reconcile。

测试使用本文建立关键验收链路：
