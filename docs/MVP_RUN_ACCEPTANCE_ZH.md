# MVP 跑局验收清单

目标：在不依赖商业试点和真实用户反馈的前提下，先证明产品可以稳定跑完一场基础剧本杀。

## 最小闭环

- 创作者可以创建或导入一个世界。
- 系统可以生成或同步 Segment。
- 每个 Segment 可以关联章节、玩家分幕、线索、主持 runbook。
- 主持人可以创建房间并拿到邀请码。
- 玩家可以加入房间并绑定角色。
- 玩家可以阅读已解锁分幕。
- 主持人可以看到玩家进度、当前 Segment、应发线索和待处理队列。
- 玩家可以完成任务、提交口供、参与投票或私行动。
- 主持人可以处理投票、私行动、口供和补救话术。
- 结束后可以查看复盘或运行报告。

## 发布前阻断项

- 没有角色。
- 有角色没有任何可发布分幕。
- 没有 Segment。
- Segment key 与章节/分幕 key 无法对齐。
- 关键 Segment 缺少主持 runbook。
- 关键 Segment 缺少线索或线索引用无效。
- 房间无法创建或玩家无法加入。
- 主持端无法加载玩家状态。
- 玩家端无法加载当前幕。

## 发布前警告项

- Segment 没有补救话术。
- Segment 没有玩家任务。
- Segment 没有复盘节点。
- 投票/指认未配置。
- 私行动未配置。
- 自动解锁规则不足。
- 主持 runbook 只有流程，没有主持真相。

## 第一批验收线

- `Segment` 是三端共同运行主轴。
- `segmentKey` / `proposalKey` / `matrixActKey` / `chapterKey` 有统一解析规则。
- `Segment.operations` 有标准结构。
- Matrix 导入后会写入 `world_segments.operations`。
- 创作者端 Segment 工作台能查看和编辑 operations。
- 主持端当前幕优先读取 `world_segments.operations`。
- 玩家端当前幕优先根据 Segment 推导。
- 旧 `settings.hostRunbooks` 只作为兼容回退。

## 本阶段明确不做

- 高级商业化：套餐、付费墙、分账、渠道结算不进入 MVP 跑局验收。
- ML 自动优化：玩后自动改稿、模型评分、自动 AB 推荐先不做。
- 复杂关系图：暂不引入图形库做完整可视化关系图，只保留结构数据与基础列表。
- 完整 A/B 内容实验：不做批量实验平台，只保留后续可接入的 Segment key 与质量数据。
- 企业级权限治理：MVP 只验证创作者、主持、玩家三类基础边界。
