# P7.4 Product Playtest Round 1 — 执行单

> 冻结基线：`6795744`  
> 原则：**原则上不开发功能**；用当前 Runtime 跑真人局。  
> 测的是工具，不是「商会库房案」文学质量。

---

## 0. 一句话目标

> 不开开发者控制台、不手改数据库、不看源码、开发者不指导操作的前提下，  
> **主持能否带 6 人把一局从开房玩到 FINISHED？**

---

## 1. 人员与环境

| 角色 | 要求 |
|---|---|
| 主持 | **最好非开发者**；最多告知「有一本已配置好的剧本，请建房带完」 |
| 玩家 | 理想 6 真人；最低 2～3 真人 + 其余浏览器代打 |
| 观察员 | 1 人只记录，不教、不点、不代操作 |
| 构建 | 分支含 `6795744`；世界已绑 READY「商会库房案」或 fixture 回退 |

**禁止**：边玩边修代码；教「点哪个按钮」；手改 DB。

---

## 2. 开场话术（仅此）

对主持：

> 「你现在有一本已经配置好的剧本。请创建房间并带大家玩完。」

对玩家：

> 「加入这个房间开始玩。」

若有人问「我现在要点哪个？」→ **先记日志，再决定是否极简提示**（提示本身也要记）。

---

## 3. 建议流程（不强制口述步骤）

观察员心里应有的期望路径（**不要念给主持听**）：

```text
创建房间 → 玩家加入 → 分配 6 角色 → 开始剧本
→ Stage1 读本 / 发线索
→ 进入 Stage2 → 开始竞价 → 出价 → 结算
→ 确认赢家是否发现新正文/线索
→ Stage3 → Final
→ 开始最终指认 → 投票 → 结算 → 确认终局 → FINISHED
```

---

## 4. 八维观察（必填）

| 维度 | 观察问题 | 记录栏 |
|---|---|---|
| 开局 | 能否不看教程完成：建房→分角→开局？ | |
| 导航 | 玩家是否随时知道「我现在该干什么」？ | |
| 内容 | 新正文/线索是否容易被发现？ | |
| GAME | 是否理解为何出现竞价/投票？ | |
| 主持 | 主持是否一直知道下一步？ | |
| 状态 | 谁没读、谁没投、谁掉线是否够清楚？ | |
| 错误 | 点错后有没有无解局面？ | |
| 结束 | 双方是否明确「本局已完成」？ | |

## 5. 事件时间线模板

```text
时刻   | 谁     | 发生了什么              | 卡点/原话
-------|--------|-------------------------|----------
00:00  | 主持   | 进入                    |
00:__  | 主持   | 找到创建房间 / 卡住在…    |
…      | 玩家X  | 「在哪里看线索？」       |
…      | 赢家   | 竞价后是否注意到新正文   |
…      | 全员   | FINISHED / 未完成原因   |
```

整局目标：从进房到 FINISHED 记满一条线。**不需要 Analytics 系统。**

---

## 6. Round 1 PASS / FAIL

### PASS（产品可毕业到下一阶段讨论）

同时满足：

1. 未开开发者控制台 / 未手改 DB / 未开源码完成一局  
2. 开发者**未实时指导**主持关键操作（或指导次数 ≤ 2 且全部记入日志）  
3. 到达 `FINISHED`，且主持与至少多数玩家知道「本局结束」  
4. 无 P0：错看他人正文、机制卡死无法继续、刷新丢局且无法恢复  

### FAIL（仍属 P7 产品债，桌测驱动后再写代码）

任一成立：

- 主持无法独立开局或无法带到终局  
- 玩家高频问「现在干嘛」（观察员主观：≥ 每 5 分钟一次且依赖主持口头救场）  
- 出现 P0 权限/卡死/丢状态  
- 必须靠开发者代点才完成  

### 不做评分的内容

不问：故事感人吗、推理精彩吗、人物立得住吗。  
只问：**软件有没有妨碍大家玩这个本？**

## 7. 桌测后产物（再决定写什么代码）

```text
P2  线索无提醒 / 提交状态不清
P3  文案美观
```

然后才进入：

```text

或

```
