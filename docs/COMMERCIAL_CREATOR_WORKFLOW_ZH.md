# 商业作者工作流与稿件安全

> 更新：2026-07-24。本文描述已经进入产品和代码的能力、部署前置条件与仍需人工复核的边界。

## 1. 稿件导入

创作者端「剧本创作 → 稿件解析与结构化导入」支持：

- TXT、Markdown：直接读取文本。
- DOCX：提取 Word 正文后进入统一结构识别。
- PDF：优先读取文字层；图片型 PDF 可选择 OCR，或按页作为角色本图片导入。
- JPG、PNG、WebP：按页作为角色本图片导入。
- 飞书新版云文档（`/docx/`）/知识库文档：服务端以只读凭据读取 Docx 内容块，再进入统一结构识别。旧 `/docs/` 链接会先查询升级后的文档 ID；尚未升级的旧版文档会明确提示作者复制或升级为新版文档，不会误走新版接口。

解析不会直接写库。作者先检查预览，再选择「完整母稿」「指定角色本」或「智能结构导入」。智能结构导入识别角色、幕/章节、场景、线索/HO 和秘密/KP 信息，所有新对象默认是草稿；线索默认仅主持可见，现有内容不会被覆盖。重复提交同一稿件采用稳定导入键去重。

识别是启发式辅助，不是出版级排版还原：复杂 Word 样式、飞书表格、图片、附件、脚注与复杂嵌套块必须人工核对；扫描 PDF 的 OCR 也必须校对错字和分段。

飞书部署需要配置 `FEISHU_APP_ID` 与 `FEISHU_APP_SECRET`，或短期使用 `FEISHU_USER_ACCESS_TOKEN`。凭据只放在后端环境变量中，不写入世界设置、浏览器或导出包。文档需给应用只读权限。

## 2. 版权、保密、删除与导出

平台执行以下产品边界：

- 私有剧本默认不公开；只有作者主动申请并通过公开库审核后才公开展示。
- 本地稿件与飞书稿件在服务器解析前，必须明确确认拥有版权或处理授权。
- 私有稿件不作为平台模型训练数据。只有作者主动调用 AI 功能时，所选上下文才可能发送给配置的模型供应商。
- 用户可以删除在线世界和附件；受限备份会按保留周期轮转清除，不能承诺删除后所有备份瞬时消失。
- 「内容包」导出提供完整结构化归档、审稿记录和附件清单，但二进制附件仍需单独下载；协作者邮箱、有效运行房邀请码不会进入归档或创作版本快照。当前内容包导入只恢复标准运行对象，不等于所有扩展域的一键灾难恢复。
- 普通公开库 `viewer` 只获得公开世界信息、角色公开简介与公开备案展示字段，不能读取结局摘要、主持补救脚本、创作者分析、内部自审备注、场景/线索工作区或版本标签。

正式商用前仍需律师复核 [隐私说明](./legal/PRIVACY_ZH.md)、[用户协议](./legal/USER_TERMS_ZH.md) 与 [版权投诉流程](./legal/COPYRIGHT_APPEAL_ZH.md)，并使实际存储、AI 供应商和备份策略与文案保持一致。

## 3. 作者术语与商业档案

世界设置中的「创作类型」驱动共享术语表：

| 底层对象 | 剧本杀 | 跑团 | 互动叙事 |
|---|---|---|---|
| role | 角色本 / 角色 | 调查员 / PC | 角色 |
| act | 公共幕 | 章节 | 章节 |
| clue | 线索 | HO | 信息卡 |
| secret | 秘密 | KP 信息 | 隐藏信息 |
| host | 主持人 | KP | 导演 |

底层 API 和数据库字段保持稳定，界面文案逐步从 `shared/creator-terminology.js` 获取，避免为不同类型复制业务逻辑。

「世界设置 → 商业作品档案」预留作者、版权来源、备案编号、主题、类别、适龄范围、版本、自审状态、自审说明、实质修改日期和备案更新日期。字段用于团队归档与发布检查，不代表平台代为备案或判断合规。商业上线应以属地主管部门要求为准；参考 [文化和旅游部办事指南](https://zwfw.mct.gov.cn/flagship/zcfg/zcfgDetail?uuid=69) 与 [地方剧本娱乐经营场所备案指南](https://www.wxlx.gov.cn/doc/2023/01/09/3861587.shtml)。

## 4. 协作者审稿

「剧本创作 → 协作者审稿」支持：

- 主创、编辑和独立 `reviewer`（只读审稿人）创建对象级批注、修改建议或阻塞交付项。公开剧本库加入者使用的 `viewer` 不具备审稿权限，避免把玩家身份误当内部审稿人。
- 批注可绑定世界、母稿、角色、章节、分幕、场景、线索、规则、真相声明或 Segment。
- 系统校验目标确实属于当前世界，并记录结构化建议与影响范围计数。
- 团队成员可回复；意见作者可修改仍开放的意见；只有主创或编辑可解决、驳回或重新打开。
- 可比较两个内容版本，显示新增、删除、修改对象及字段名。为降低泄稿风险，差异结果不直接返回私人正文。

部署前必须先执行迁移 `091_creator_review_workflow.sql`，否则审稿接口不可用。审稿表启用 RLS，不授予 Data API 访问；应用通过后端世界成员权限检查访问。

玩法 Profile、不可变发布版本和运行房绑定还依赖 `092_narrative_profile_settings.sql`、`093_world_releases.sql` 与 `094_room_release_binding.sql`。当前房间可预绑定 Release，但在运行内容读取器全面完成前仍使用兼容读取并显示明确警告；不得把“已选择版本”宣传成“正式冻结运行”。

## 5. 主持人的临场自由

正式主持入口是 Host 端。打开玩家详情后，主持人可查看「该玩家现在知道什么」，包括角色本进度、已持有线索、调查与近期记录，并可：

- 手工解锁分幕；跳过并标记完成；撤回已解锁的非首个分幕。
- 发放、补发或撤回某玩家的线索。
- 使用既有规则预览、手动触发、待确认处理、小游戏强制完成和玩家管理能力。

所有新增覆盖操作采用幂等写入，并把状态变化、主持时间线、审计日志和 SSE outbox 放在同一数据库事务中。撤回只改变系统当前可见状态，不能抹除玩家已经看过的内容、笔记或审计证据；界面会明确警告主持人。

## 6. 部署与验收清单

1. 先在隔离数据库执行全部迁移，确认包含 `091_creator_review_workflow.sql`。
2. 配置飞书只读应用并用无权限、有权限、已删除、超大文档各验证一次。
3. 用 DOCX、文字 PDF、扫描 PDF、角色本文件名和混合术语稿件验证预览与结构落点。
4. 验证未勾选版权确认时，本地与飞书解析、导入都被后端拒绝。
5. 用 owner/editor/reviewer/viewer/host 五类成员验收审稿权限和 Studio 数据投影；普通 viewer 与 host 都不应读取内部审稿内容，viewer 也不应读取结局、内部设置、创作者分析或运行房邀请码。
6. 在 Host/Player 双端验证补发、撤回、解锁、撤回分幕、跳过，以及断线重连后的最终状态。
7. 导出内容包，核对扩展结构和附件清单；另行下载二进制附件并完成恢复演练。

隔离 PostgreSQL 可用时，在 `backend` 目录执行 `npm run test:commercial-creator:isolated`，会创建临时数据库、迁移、种子、运行本模块数据库完整性用例并销毁临时库。安全护栏会拒绝把该命令指向生产或未明确隔离的数据库。
