# 创作驾驶舱故事总览 V1

## 目标

“故事总览”是散落创作材料与后续生产模块之间的装配层。它把世界简介、灵感、创作宪法、角色、关系、核心事实和章节整理成一份可阅读、可确认、可继续生产的故事主干。

它不替代作者，也不把 AI 输出直接视为正式设定。

## 用户流程

1. 作者在原有驾驶舱中填写灵感、梗概、角色、关系、事实和章节等材料。
2. 后端读取当前世界快照，生成“候选故事总览”。
3. 前端仅展示候选与变化，不自动写入项目。
4. 作者可以放弃候选，或采用为当前故事总览。
5. AI 草拟的核心区块可逐项确认为作者设定；后续重新装配时，这些区块必须原文保留。

## 故事主干结构

- 一句话故事
- 整体故事
- 开场状态
- 引爆事件
- 核心冲突
- 玩家为何必须参与
- 玩家反复执行的行动
- 真相与核心转折
- 六名角色在故事中的不可替代作用
- 章节因果主干
- 累积结局方向
- 待作者决定的问题与暂定假设

每个核心区块有三种状态：

- `author_confirmed`：作者已经确认，AI 不得静默覆盖。
- `ai_draft`：AI 根据现有材料整理的候选表述。
- `unresolved`：现有材料不足，需要作者决策。

## 模块边界

| 层级 | 文件 | 职责 |
| --- | --- | --- |
| 共享契约 | `shared/story-spine.js` | 归一化、状态确认、已确认区块保护、差异与覆盖率 |
| 后端装配 | `backend/src/story-spine-assembler.js` | 构建带稳定引用的材料目录、调用模型、校验结果、恢复作者确认内容 |
| 请求校验 | `backend/src/routes/schemas/ai.js` | 装配接口输入边界 |
| 存储校验 | `backend/src/routes/schemas/world-settings.js` | `world.settings.storySpine` 的完整结构约束 |
| API 路由 | `backend/src/routes/story-assistant-routes.js` | 鉴权、读取世界快照、返回候选版本 |
| 前端渲染 | `src/views/creator-cockpit-story-spine.js` | 空状态、候选、当前版本、状态标识和操作入口 |
| 前端动作 | `src/runtime/actions-creator-cockpit.js` | 组装、采用、放弃、逐项确认 |

## 数据与安全约束

- 模型只能引用后端提供的材料目录，所有 `sourceRefs` 必须对应真实目录项。
- 无法由现有材料支持的内容必须进入 `assumptions`，不得冒充作者事实。
- 候选版本只保存在驾驶舱草稿中；只有作者点击“采用”才写入 `world.settings.storySpine`。
- 已确认为 `author_confirmed` 的核心区块在服务端再次强制恢复，不能只依赖提示词约束。
- 前端统一转义所有模型输出，禁止把远端文本作为 HTML 注入。
- 装配接口使用现有世界权限与 LLM 上下文守卫，不在浏览器中持有平台模型密钥。

## 后续模块的使用原则

后续角色、章节、机制和文稿生成应读取故事总览，但不能把它当成唯一事实源：

- 角色创作读取 `playerPremise` 与 `roleFunctions`。
- 章节编排读取 `chapterArc` 的原因、行动、转折和后果。
- 机制设计读取 `mechanismLoop`，并继续补足输入、反馈、代价与失败推进。
- 文稿生产读取 `overview`、`truthAndReversal` 与 `endingDirections`。
- 发生冲突时，以作者已确认区块和创作宪法为优先事实。

## 测试入口

- 后端契约与保护规则：`node --test backend/test/story-spine.test.js`
- 前端结构与操作契约：`node --test scripts/creator-cockpit-story-spine.test.mjs`
- 交互断链：`npm run check:ui-interactions`
- 生产构建：`npm run build`

## V1 暂不包含

- 对章节、角色与结局数组逐条确认。
- 在故事总览中直接进行富文本编辑。
- 自动把总览反向覆盖到角色或章节。
- 多模型复核与机制模拟结果的前端展示。

这些能力应在 V1 数据稳定后逐步增加，避免故事总览再次变成一个过重的万能编辑器。
