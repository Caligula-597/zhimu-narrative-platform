# AI 剧本生成系统批评意见整改对照

更新日期：2026-08-15

## 1. 本轮结论

这批意见的核心不是“继续增加写作禁令”，而是要求系统从单向提示词流水线转向可定位失败、可局部回退、可模拟和可审计的叙事状态引擎。

现阶段应保留创作驾驶舱的作者认知顺序，但不能把它实现成只能从头重算的瀑布线。正确结构是：作者按“概念—事实—人物—线索—流程—文稿”逐层确认；系统在层间维护依赖图、负向知识、共享事件和局部失效范围，允许下游发现问题后回到最早受影响的层。

本轮不采用“看到一条问题就在真人化提示词里追加一句”的做法。整改分为三类：

- **立即落地**：已有数据足以实现，且能直接降低错误成本；
- **加强既有能力**：项目已有雏形，补足缺失维度；
- **状态引擎建设**：需要持久化、模拟或产品界面配合，先建立合同和审计输出，不假装一次提示词改动已经完成。

## 3. 本轮实施边界

### 立即修改

1. 负向认知边界；
2. 共享互动合同；
3. 多种场景变化模式；
4. 线索依赖独立性；
5. 三种线索干扰结果；
6. 作者立场表述；
7. 过度功能化审查；
8. 角色必要性与删角静态模拟；
9. 失败路由和局部修复计划；
10. Matrix 前置 dry run；
11. 对抗性评判；
12. 术语 provenance 分类。

### 状态引擎收尾（已落地）

1. 真相—人物自动往返生成：本轮先产生可执行的回退请求，不让模型擅自改真相；
2. 字段级 semantic invalidation：已生成语义节点 DAG、字段 diff、传递失效路径与前端“局部过期”状态；
3. 100 次策略压力测试：已接生成、评判和入库门禁；它是确定性结构压测，真人情绪与表演体验仍交给真人测试；
4. 主结局 × 角色尾声修饰项：已同步 truth、import、mechanism runtime、API schema 与玩家结局界面；
5. 统一生成审计：已持久化字段指纹和 AI/人工来源，不新增数据库列，使用现有 JSONB settings/metadata 通道。

## 4. 设计原则修正

- 顺序是作者认知顺序，不是不可逆执行顺序。
- 事实先于玩家正文，但事实与人物利益必须联合收敛。
- 信息隔离包括“不能知道”和“还不能推断”，公共行为共享、私人解释隔离。
- 场景必须发生可观察变化，但不必每场都有显性胜负。
- 公平要求可获得与可反制，不要求结果平均，也不要求毁证必留可归因脚印。
- 作者可以有立场，玩家不能被系统强迫证明该立场。
- 后台字段只有在能改变玩家经历、失败定位或运行结算时才值得存在。

## 5. 完成标准

本轮只有在以下条件同时满足时才算完成：

1. 对照表中的“立即修改”均有代码或提示词落点；
2. 新合同有验证器或审计输出，不能只写文档；
3. 旧《借影》样本仍通过，证明兼容层没有误伤已有内容；
4. 新增回归测试覆盖认知泄露、共享事件、非冲突场景、伪独立路径、毁证模式、陪跑角色和失败路由；
5. 明确报告尚未完成的状态引擎工作，不用“已经支持”掩盖只有接口的功能。
