# 织幕竞品定位与宣发简报（2026-07-30）

研究日期：2026-07-30
时间范围：以当前可访问的公开产品页为准
目标人群：已有剧本或长线互动叙事内容、准备线上测试或运行的作者、小型工作室与主持人
研究范围：创作组织工具、中文剧本创作平台、VTT / 跑团运行平台、沉浸式叙事工具

> 本页是公开信息快照。观察来自产品官方页面；“对织幕的启示”属于产品推断，不等同于竞品已验证的用户研究。

## 1. 执行结论

当前市场大致分为两端：

- 一端擅长“把故事写清楚、组织好”：World Anvil、Campfire、Milanote、剧云等。
- 一端擅长“把桌面角色扮演跑起来”：Foundry VTT、Alchemy、Quest Portal 等。

织幕不宜在任一端与成熟产品比“功能总量”。更清晰的机会是补上中间断层：

> **把一份完成或接近完成的剧本，转换成按角色权限运行的多端体验；让主持现场可控，让每次运行结果继续推动改本。**

这使织幕的差异不只是“能写”或“能玩”，而是“能从母稿走到首场，再从首场回到下一版”。

## 3. 竞品共同强项

### 3.1 创作工具的共同强项

- 入口直接讲用户任务，而不是技术架构。
- 使用人物、时间线、地图、卡片和大纲等作者熟悉的对象。
- 强调“在一个地方组织全部内容”“看清全局”“更快找到资料”。
- 模板和示例比空白表单更重要。

### 3.2 VTT 的共同强项

- 邀请与加入路径清晰。
- GM / Player 角色区分明确。
- 用实际场景、角色或地图画面证明沉浸感。
- 官网常用真实玩法画面而不是后台功能清单。

### 3.3 中文剧本平台的共同强项

- 直接使用“剧本、人物、场景、节拍、改稿、协作”等专业中文词。
- AI 被包装成诊断、改编、拆解和辅助，承诺比“一键生成”更具体。
- 导入旧稿和进入统一项目空间，是降低迁移成本的重要抓手。

## 4. 织幕可占据的位置

### 4.1 核心差异化

| 差异 | 用户价值 | 宣发证据 |
|---|---|---|
| 创作与运行不是两套断开的工具 | 写完后不需要再用群聊、表格和多个 Bot 拼现场 | 从导入到开房的完整演示 |
| 创作者、主持人、玩家三端同源分权 | 每个人看到正确内容，秘密和进度不靠人工记忆维护 | 同一场景的三端对照截图 |
| 模板与运行房分离 | 同一剧本可多次测试，多房进度互不污染 | 一份剧本下的多房列表和不同进度 |
| 主持只处理关键节点 | 自动同步常规状态，主持把精力留给节奏与临场判断 | 待确认、玩家进度、卡关提醒 |
| 运行结果进入改本 | 复盘不是总结文章，而是定位到幕、线索和操作 | 运行报告到修改任务的演示 |

### 4.2 最有利的市场楔子

首个可验证场景不应是“从零用 AI 生成一部大作”，而应是：

> **已有一份 Word / PDF / 飞书剧本，想在一周内开出第一间线上测试房。**

这个场景具备明确输入、明确结果和明确付费服务空间，也能自然展示导入、角色权限、主持、玩家和复盘。

## 5. 宣发信息架构

### 5.1 官网首屏

眉题：

> 线上剧本创作与运行平台

主标题：

> **把一个剧本，运行成一场真正同步的故事。**

解释：

> 创作者写结构，主持人控节奏，玩家只看到此刻该知道的内容。三端使用同一份故事数据，线索、进度和现场操作不再靠群聊与人工记忆拼接。

主 CTA 建议测试：

> **导入我的剧本，跑首场测试**

次 CTA：

> 看 3 分钟真实演示

### 5.2 四段证明顺序

1. **已有稿件也能开始**：导入、识别、确认角色与章节。
2. **三端看到正确视角**：同一内容，不同权限。
3. **一份剧本开多个房**：每房进度、线索与结局独立。
4. **每场运行留下改本依据**：复盘定位到具体问题。

### 5.3 不再作为首屏主卖点

- Fastify、PostgreSQL、SSE、迁移数、测试数等工程指标。
- “AI 创作助手”本身。
- 过多系统模块名和后台能力。
- 剧本市集、教育、企业培训等尚未形成当前主闭环的远期场景。

这些内容适合评委材料、技术文章或后续商业页面，不适合抢占主价值主张。

## 6. 内容选题

### 本周可做

1. 《一份 Word 剧本，怎样在织幕里开出第一间测试房》
2. 《主持人不再当人工数据库：线索、进度和待确认怎样同步》
3. 《同一个剧本开三间房，为什么彼此不会串线》

### 本季度可做

1. 一个真实 pilot 从导入到复盘的完整案例。
2. 三端同屏演示：创作者发布、主持推进、玩家收到内容。
3. “跑完一场以后具体改哪里”的复盘改本案例。
4. 作者主权专题：AI 如何辅助检查，而不是替代创作者。

## 7. 渠道协调

| 渠道 | 主要受众 | 只讲一件事 | 主要素材 |
|---|---|---|---|
| 官网 | 作者 / 工作室 | 从稿件到首场测试 | 三端真实截图 + 四步流程 |
| 创意比赛 / 路演 | 评委 / 合作方 | 产品闭环和差异化系统能力 | 真实演示 + 当前可复核数据 |
| 知乎 / 公众号 | 作者 / 主持 | 解决真实工作流问题 | 方法文章 + 前后对比 |
| 小红书 / B 站 | 玩家 / 年轻创作者 | 角色视角和长线沉浸 | 竖屏流程、三端切换、故事片段 |
| 定向工作室邀约 | 已有剧本团队 | 一周内协助开首场 | 人工导入服务 + 交付清单 |

## 8. 当前品牌协调问题

| 物料 | 当前状态 | 处理建议 |
|---|---|---|
| 官网与三端产品 | 米白、墨绿、铜金，编辑部 / 剧本工作室气质 | 作为当前品牌真相源 |
| 创意提案 HTML | 黑金科技风，强调历史工程数字 | 保留历史版；新增与官网一致的当前品牌版 |
| 报名帖 | 定位清楚，但偏“自动化引擎”与功能罗列 | 改成“从稿件到首场”的用户故事 |
| 产品内 Creator | 能力深，但异常、演示和登录信息重复 | 先做信息层级收口，再增加功能 |
| Host | 角色明确，但错误对象和空状态仍暴露工程感 | 优先修复错误转换和选房引导 |
| Player | 入口最清楚，角色视角鲜明 | 作为三端文案与空状态的参照样板 |

## 9. 研究限制

- 本轮主要使用公开官方产品页，没有访问竞品登录后的完整工作流。
- 未获得竞品用户规模、留存或付费转化的可比数据。
- 中文剧本杀工具市场较分散，公开页面不一定代表其真实交付深度。
- 因此，本页适合指导定位和宣发假设，不适合直接推导市场份额或定价。
