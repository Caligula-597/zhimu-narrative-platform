# `灵感.doc` 产品输入追踪表

最后更新：2026-07-24

## 用途

仓库根目录的 `灵感.doc` 是创始人的原始产品观察与风险假设。它保持原文，不作为接口、上线状态或法律承诺。本文把每条输入映射到当前产品、代码证据和后续模块，避免“写进想法后没人知道是否处理”。

状态含义：

- **已落地**：代码和产品入口已经存在，仍需按发布版本验收。
- **部分落地**：底座或第一版存在，但用户目标尚未完全满足。
- **待设计/待验证**：不能在对外文档中描述为已上线。

## 系统不变量映射

| 不变量 | 主要保证位置 | 证据入口 |
|---|---|---|
| 用户 A 不能读写用户 B 的世界 | 后端世界成员/所有权检查、资源归属查询、RLS 防御层 | `test:permissions-matrix`、IDOR/跨世界 service 测试、[身份与权限](./IDENTITY_AND_PERMISSIONS.md) |
| 房间 A 的事件不能进入房间 B | journal/outbox 的 `room_id`、服务端订阅授权与受众投影 | `test:sse-matrix`、[SSE 故障矩阵](./SSE_FAILURE_MATRIX_ZH.md) |
| 玩家不能看到未公开内容和其他角色秘密 | 查询阶段按 room member/role 投影，不依赖前端隐藏 | 玩家内容、导出、复盘、搜索、SSE 专项权限测试 |
| 已提交业务不能因通知失败返回失败 | 业务事务写 outbox，提交后 dispatcher/NOTIFY/poll 补偿 | outbox、notify failure、replay subscription 测试 |
| 重试不能重复发线索、计分或推进 | `Idempotency-Key`、幂等 claim、数据库锁与唯一约束 | idempotency coverage、并发 Host/Player 写测试 |
| 断线重连不漏事件、不重复执行 | 持久 journal、账号隔离 cursor、replay/live 去重、poll reconcile | `test:sse-matrix` |
| 代码回滚时数据库仍兼容 | 前向迁移、N-1 验证、应用只依赖已部署 schema | [发布恢复与回滚](./operations/RELEASE_ROLLBACK_ZH.md) |
| 管理、调试、导入不能绕过权限 | OPS token、生产禁 demo header、导入 world 权限与资源归属 | production-ready、危险入口扫描、权限矩阵 |
| 任意失败可追踪、恢复、解释 | request/trace id、结构化错误码、审计、checkpoint、告警 | [错误码](../backend/docs/API_ERRORS.md)、[非功能审计](./NONFUNCTIONAL_AUDIT_ZH.md) |

## 更新规则

1. 不修改 `灵感.doc` 的原始措辞；产品决策写到本文和对应正式设计。
2. 状态从“待设计”改为“部分落地”时，必须能指向代码入口或 migration。
3. 状态改为“已落地”时，必须同时有前端入口、后端契约、权限/失败路径和验收证据。
4. 构建、静态扫描或测试声明存在，不能单独证明真实浏览器体验已经通过。
