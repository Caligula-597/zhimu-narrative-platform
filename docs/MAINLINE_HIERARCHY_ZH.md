# 新主线生成层级：地点场合与场景地点展开

最后更新：2026-09-27

## 当前定位

这是剧本杀创作端当前唯一的主线创作入口。它负责把创作从客观空间和持续性场合开始，逐层推进到故事、对抗和重点内容绑定；它不是外部剧本导入，也不是完整母稿编辑器。

外部已有剧本继续走开本包 / 文档导入管线；导入后的角色、场景、线索和母稿仍由原有内容工具负责。新主线层级只管理创作者从地点开始的新建主线草稿。

## 层级关系

```text
L1 地点与公共场合选择
  ↓
L2 场景地点展开
  ↓
L3 故事公开文面
  ↓
L4 完整故事展开
  ├─→ L5 主要对抗来源决策
  ├─→ L6 后期对抗结构决策
  └─→ L7 故事重点内容与来源绑定
```

L5、L6、L7 都以 L4 为前置。L7 不强行等待 L5/L6，因为内容绑定和后期对抗是从完整故事分出的并列创作分支。

## 每层边界

| 层级 | 负责 | 明确不做 |
|---|---|---|
| L1 | 地点、持续性场合、地点 + 场合组合 | 房间、线索、事件、机制、移动关系 |
| L2 | 角色房间、特殊多人场所、基础公共地点 | 剧情事件、线索、解锁条件、玩家移动 |
| L3 | 客观故事母题、背景和当前事件 | 角色秘密、机制、线索卡、主持流程 |
| L4 | 历史因果、地点来源、角色客观交集、当前事件 | 玩家私人剧本、搜证轮次、机制、主持流程 |
| L5 | 外部对抗、内部对抗或混合对抗及判断依据 | 阵营、秘密、个人任务、具体机制 |
| L6 | 立场形成、结果结构、倡议方式和最终结算结构 | 强行分配阵营、指定支持关系 |
| L7 | 重点、类型、载体、来源地点、解释/铺垫/回收 | 玩家探索流程、交付流程、玩家视角信息差 |

## 前端行为

入口位于剧本杀创作页 Writer 的「新主线层级」。首次创建剧本杀项目后也会进入该入口。

- 每个项目独立保存一份草稿。
- 前置层级未锁定时，下游层级不可进入。
- 当前层必填字段未完成时，不能锁定。
- 解锁上游后，已锁定的下游层级转为“待补前置”。
- 保存和锁定都会写入云端；浏览器 `localStorage` 只作为离线回退缓存。
- 主线层级不把内容自动写入角色本、线索或搜证流程；后续内容生成必须明确使用已锁定层级。

## API 与数据库

主应用仍使用现有端口：

- 前端开发：`http://127.0.0.1:4173`
- 后端 API：`http://127.0.0.1:4180`
- 前端请求路径：`/api/worlds/:worldId/mainline-hierarchy`

接口：

| 方法 | 路径 | 权限 | 作用 |
|---|---|---|---|
| `GET` | `/api/worlds/:worldId/mainline-hierarchy` | 项目成员可读 | 读取主线层级草稿 |
| `PUT` | `/api/worlds/:worldId/mainline-hierarchy` | 项目编辑者 | 保存完整层级草稿并推进 `content_revision` |

数据存储在 `mainline_hierarchy_drafts`，迁移文件为 `backend/migrations/133_mainline_hierarchy_drafts.sql`。写入遵循现有 `If-Match` 版本冲突保护，不复用 `story_manuscripts`，避免和外部导入 / 母稿管线混淆。

## 继续开发约束

1. 新增生成能力必须明确声明读取哪些已锁定层级。
2. 不得把 L1/L2 的客观地点字段直接解释成线索或玩家行动。
3. 不得让 AI 越过未锁定层级生成后续内容。
4. 外部剧本导入仍走 `opening-package`、Compiler V2 和文档导入接口。
5. 桌游、跑团功能不接入本接口；产品域边界保持不变。
