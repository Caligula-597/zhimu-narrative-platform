## 1. 结论先行

当前项目已经具备可运行的三端主链路，不是只有静态页面：`segmentKey` 能把运行段落、地图地点、主持当前幕和玩家当前目标连起来；主持人能够实时切幕、切地点、公开地图、触发遭遇、发起判定、写入变量并公开结局；玩家端已有主持流程卡、地图、环形扫描、打乱抽线索、机制提交、主语音房与开场后密谈。

但三端尚未达到“所有基础功能都同等完整”的状态。主要差距是：

1. **关键实时状态此前只在玩家“现在”页可见。** 玩家停在调查或剧情页时会错过主持触发的遭遇。该 P0 已在本轮修复并补回归测试。
2. **线索能力的软件骨架完整，示例内容没有完成地点/调查点绑定。** 创作者端审计显示 3 条线索中 0 条有关联，玩家因此只能看到空线索区；这不是玩家端没有线索页，而是内容契约未真正落地。
3. **主持端能控制地点公开，但看不到玩家“环形扫描 → 洗牌 → 抽取”的细粒度进度。** 玩家有完整表现，主持只有结果侧数据，缺少现场调度所需的发现过程视图。
4. **主持节奏计时器仅本地可见。** 玩家能收到提醒，但看不到权威倒计时、延时或暂停状态。
5. **结局公开可以实时同步，但“公开结局 → 生成复盘 → 玩家进入复盘”仍是三个动作。** 缺少一次性收束事务和失败恢复提示。
6. **真实音频媒体链路未在隔离 fixture 中完成端到端验证。** 界面、成员投影、主房/密谈权限和 LiveKit 单元测试存在，但仍需在具备 LiveKit 凭据的 staging 做媒体验收。

## 4. 主持端实时调配专项

### 4.1 已完整闭环

- **切幕**：点击主持当前幕 → 写入 `activeSegmentKey` → 按 `segmentKey` 匹配地图地点 → 清除旧判定/遭遇 → 玩家 current beat 与地点同步。
- **切地点**：主持指定地点 → 自动加入揭示集合 → 玩家端收到公开地点、当前地点和可见路线。
- **地图权限**：可隐藏全图、单独公开/隐藏非当前地点；当前地点强制保持公开。
- **遭遇**：只允许触发当前地点已配置的 NPC；触发会清除判定并强制公开当前地点；结束遭遇保留地图进度。
- **判定**：可使用创作者预设或临场创建；玩家先看目标，主持公开掷骰后才看结果；变量只在主持确认后写入。
- **结局**：条件计算提供候选和接近度，但最终公开仍由主持确认，避免自动提前剧透。
- **人工补救**：可发线索、发物品、解锁分幕、写主持日志、发提醒、处理秘密行动/口供和创建检查点。

### 4.2 仍不够完整

- 主持没有统一的“玩家当前看到什么”镜像；需要在地图、线索、语音、机制之间跳转判断。
- 地点扫描与抽牌只存在于玩家本地展示会话，主持看不到谁仍在扫描、谁已抽到第几条。
- 主持节奏计时器是本地工具，不是房间状态；刷新、换主持设备或协主持接管会丢失。
- 当前房间没有自动化规则时，系统会提示警告，但缺少“一键从创作者推荐规则生成本房规则”。
- 遭遇/判定/结局之间虽有互斥清理，但没有一条可视化状态机说明主持下一步和不可逆动作。

## 5. 玩家视角的真实情境检查

### 5.1 玩家进入前

- 想知道：这是什么类型的故事、预计多久、我的设备和麦克风是否可用、谁是主持人、还有谁没到。

### 5.2 候场

- 想交流：和全员、主持人打招呼；确认是否能听见；不应提前开小房绕开全桌。
- 当前情况：规则正确，候场只开放全员主房；正式开场后才开放密谈。

### 5.3 正式游玩

- 想持续知道：现在发生在哪里、全桌要做什么、我能做什么、还在等谁、主持刚刚改变了什么。
- 当前情况：“现在”页给出当前幕、目标、提示、地图、机制和下一步；此前离开该页会漏掉遭遇，本轮已用全局状态条修复。

### 5.4 调查与线索

- 喜欢的交互：地点文案按剧本替换，但操作保持一致；短暂环形扫描制造悬念；线索洗牌逐张抽取；已授权但未抽取的内容不提前泄露。
- 当前情况：上述表现已实现，并支持减少动态效果偏好；但调查页和“现在”页地图割裂，主持也看不到抽取过程。

### 5.5 博弈与密谈

- 想交流：公开讨论、私下承诺、秘密选择、询问主持、临时语音密谈；希望明确哪些内容会公开、何时锁定。
- 当前情况：机制提交模式和语音密谈权限较完整；缺少统一的隐私说明组件，文案分散在各功能里。

### 5.6 结局与复盘

- 想看到：我的选择造成了什么、哪些线索错过了、角色关系如何变化、是否可以保存或重看。
- 当前情况：可以看到主持公开的结局和最新复盘；因果链、错过内容和历史局浏览不完整。

## 7. 问题清单与优先级

### P0：会让现场玩家错过关键状态

#### P0-01 非“现在”页签看不到主持关键状态 — 已完成

- 原因：遭遇、判定和结局只由 `renderGameHome()` 内的地图舞台渲染；实时数据到达时，调查/剧情/博弈页虽刷新但没有可见承载组件。
- 改动：在游戏主壳增加全局关键状态条；按“进行中遭遇 > 当前判定 > 已公开结局”优先级展示；支持一键返回当前场景；实时局部 patch 会同步更新。
- 验收：玩家停留调查页，主持触发遭遇后 15 秒内出现状态条；点击后看到 NPC；主持结束后状态消失。

#### P0-02 真实语音媒体链路缺少 staging 验收 — 待处理

- 责任：实时音频/后端 + QA。
- 依赖：可用 LiveKit staging 凭据、至少 1 主持 + 2 玩家浏览器上下文。
- 验收：候场主房全员可见可听；开场前无法创建密谈；开场后受邀用户可进入且未受邀用户无法订阅；刷新后回到正确房间；结束场次后密谈关闭。

### P1：主路径能运行，但现场调度或理解明显不完整

#### P1-01 地点线索绑定完整性门禁

- 责任：创作者端 + 发布校验 + QA。
- 工作：把“关键线索无地点/调查点/段落绑定”提升为发布阻塞；提供批量绑定和玩家视角预览。
- 验收：关键线索无法在 0 路径状态下发布；普通线索必须明确标记“允许游离”或完成至少一种路径绑定。

#### P1-02 主持端玩家发现进度镜像

- 责任：玩家端事件 + 后端状态 + 主持端。
- 工作：持久化 `scan_started / scan_ready / clue_drawn`；主持按角色查看地点、扫描状态、已抽/剩余数量，不显示未授权正文。
- 验收：主持能判断谁卡在等待、谁尚未抽牌；权限测试证明主持以外的玩家不能看到他人抽牌次序。

#### P1-03 调查页与当前地图合并

- 责任：玩家端。
- 工作：调查页顶部显示紧凑当前地点/地图入口；全局状态条跳转后保持用户上下文；避免同一地点在“现在”和“调查”出现不同状态。
- 验收：切地点后玩家在调查页 1 秒内看见当前地点变化；移动端首屏无需滚动超过一屏才能确认位置。

#### P1-04 房间级节奏计时器

- 责任：后端 + 主持端 + 玩家端。
- 工作：把开始、暂停、延长、重置和截止时间保存为房间状态；主持/协主持一致；玩家只看创作者/主持允许公开的计时器。
- 验收：主持刷新和协主持接管不丢时间；断线恢复误差小于 2 秒；未公开计时器不投影给玩家。

#### P1-05 结局到复盘的一次性收束

- 责任：后端 + 主持端 + 玩家端。
- 工作：提供“公开结局并准备复盘”事务；生成失败可重试，不撤回已公开结局；玩家显示准备中/可查看状态。
- 验收：重复点击幂等；断线重连后结局和复盘状态一致；玩家不看到主持私密复盘字段。

#### P1-06 断线/刷新可解释状态

- 责任：三端运行时 + QA。
- 工作：展示最后同步时间、当前游标、重连原因和追平完成提示；对输入中的玩家延迟刷新并明确说明。
- 验收：SSE 中断 10 秒后恢复不重复执行动作；刷新后仍在原房间、角色和语音策略；关键状态与主持一致。

### P2：扩展性和体验完善

- **P2-01 物品动作契约**：使用、消耗、组合、对角色/地点使用及主持确认。
- **P2-02 交流动作模板**：创作者统一配置口供、公开陈述、秘密行动和询问主持的标题、隐私说明与截止时间。
- **P2-03 关系状态演变**：主持可授权公开部分关系变化，玩家看自己的关系轨迹。
- **P2-04 小游戏插件协议**：统一开始、提交、超时、失败恢复、主持结算和复盘数据。
- **P2-05 多局复盘库**：玩家按世界/角色查看历史局，支持删除/导出与隐私期限。
- **P2-06 三端无障碍验收**：键盘顺序、焦点、屏读、200% 放大、减少动态效果和颜色对比。

## 10. 证据限制与剩余风险

- 隔离浏览器 fixture 验证了状态和权限界面，没有连接真实 LiveKit 媒体服务器；因此不能宣称真实音频已验收。
- 本机数据库安全门拒绝使用当前生产外观连接运行写入型权限/语音套件；改用无数据库写入的 SSE 受众矩阵完成权限验证。语音数据库集成测试仍列为 P0-02 staging 任务，未以跳过安全门的方式强行执行。
- 本轮只对一个标准测试世界做完整互动；多角色、多协主持、不同发布版本和 20+ 玩家压力需另做矩阵。
- 创作者地图是桌面设计工具，本轮没有完成触屏拖拽和屏读地图编辑验收。
- 环形扫描和线索洗牌当前是玩家本地展示会话；刷新后重建，不是跨设备持久化的“抽牌事实”。在接入主持发现进度前，不能用于需要严格牌序审计的剧本。
- 示例世界的线索绑定缺失会显著拉低玩家调查体验，应与代码缺陷分开跟踪，但必须在正式发布门禁前解决。
