## 1. 交付结论

本轮已经完成基线审计中所有可在代码库和隔离验收环境内完成的 P0/P1/P2 工作。三端现在共用稳定运行契约：创作者负责可替换内容和策略，主持负责现场授权与节奏，玩家只接收自己的公开/角色投影。固定的是交互骨架、视觉语言和协议，不是剧本正文。

完成范围包括：

- 创作者可配置地点扫描文案、线索路径、物品动作、交流动作、关系、小游戏和复盘相关内容；关键线索没有明确发现路径时阻止发布。
- 主持可看到玩家发现进度，持久化控制倒计时，处理物品动作、关系公开、小游戏恢复/结算，并用一次幂等动作公开结局和准备复盘。
- 玩家在“现在”和“调查”看到一致地点；可按地点扫描、洗牌、抽取；任意页签都不会漏掉遭遇/判定/结局；刷新和断线后会显示原因、游标、最后同步时间及追平确认。
- 候场只允许包含主持/协主持/玩家的全员主语音房；正式开场后才开放受邀密谈。客户端会用最新房间策略覆盖旧快照，并在进入语音页时再次向服务端对账。
- 所有新增运行状态都有服务端权限投影、乐观并发版本、幂等或事务边界及 SSE 恢复路径。

唯一不能在本机签字的是“真实 LiveKit 音频包是否在 staging 成功传输”。三人浏览器媒体门禁已经实现，但当前环境没有 staging URL、短期账号令牌和 LiveKit 凭据。该项是外部环境执行门禁，不是未实现代码。

## 3. 三端最终职责边界

| 能力 | 创作者端 | 主持端 | 玩家端 |
|---|---|---|---|
| 地点与线索 | 配置地点、`segmentKey`、可替换悬念文案和发现路径 | 切地点、控制公开范围、看每位玩家的扫描/抽取计数 | 只看已揭示地点和已授权线索；服务端决定牌序事实 |
| 现场节奏 | 提供预计时长和默认机制参数 | 控制房间级时钟、暂停、延时和公开 | 只在允许公开时看服务端校准倒计时 |
| 遭遇/判定/结局 | 配置 NPC、判定、变量和条件结局 | 决定触发、掷骰、确认变量、公开结局 | 看单一公开结果和已确认因果，不接收候选/主持备注 |
| 语音与交流 | 配置交流入口和隐私文案 | 主房主持、正式开场、处理秘密行动 | 候场全员交流；开场后邀请密谈；未受邀者无令牌 |
| 扩展玩法 | 配置物品动作、关系和小游戏模板 | 审批、恢复、结算及公开范围 | 提交带版本动作，冲突后刷新权威状态 |
| 复盘 | 配置可公开真相和保留策略 | 一次性收束并重试复盘生成 | 浏览自己的历史局、导出或隐藏个人入口 |

这套边界保证“页面风格和操作形式稳定、具体剧本内容可替换”。地点扫描不是写死某个审查室；任意剧本都可替换扫描标签、等待提示、解锁文字、集合名称、数量模板和档案标签。小游戏也不再由数字锁页面决定协议，而是由版本化适配器承载具体玩法。

## 4. 后端维护与长期演进

### 4.1 单一扩展状态底座

迁移 `110_room_experience_states.sql` 新增 `room_experience_states`，用以下组合键承载房间扩展状态：

`room_id + state_kind + scope_key + subject_key`

它同时提供：

- `schema_version`：允许状态按种类渐进升级；
- `visibility`：明确 host / role / room / public 边界；
- `revision`：所有写入使用乐观并发，陈旧客户端不能覆盖新状态；
- `expires_at`：临时状态可清理；
- 64 KiB payload 上限、类型规范化器和索引；
- 房间级级联删除及 RLS 开启。

地点发现、节奏时钟、结局事务、复盘偏好、物品动作和关系状态共用这套底座。以后增加新互动时先注册 `state_kind` 和应用层验证器，不需要为每个 UI 玩法进行一次大表迁移。

### 4.2 事务与权限

- 发现抽取、物品消耗/组合、关系更新、时钟和结局均在服务端校验当前修订号。
- 业务写入与房间事件通过事务事件队列提交，避免“数据库已写但客户端未收到”或相反情况。
- 主持投影可以看调度计数，但不能看到玩家未授权正文；玩家投影移除主持笔记、隐藏地点、条件结局、内部结算和他人私密顺序。
- 未登记事件默认主持可见，不会因为新增事件名意外广播给玩家。

### 4.3 迁移质量门禁

`backend/scripts/verify-migration-upgrade.mjs` 现在不再只检查旧迁移的文件名特例，还验证：

- `room_experience_states` 的列、索引、RLS；
- 交流动作的 `public_statement` / `public` 约束和索引；
- 小游戏协议列、状态约束和截止索引；
- N-1 应用最后一条迁移前后，当前迁移标记确实从“不存在”变为“存在”。

`backend/test/room-experience-migration-contract.test.js` 另提供无数据库写入的静态契约回归。真实升级/恢复演练仍必须在隔离 PostgreSQL 上运行，安全门禁止对生产外观数据库执行。

## 7. staging 真实语音签字方法

准备一个专用 staging 房间：一名主持和两名已入房玩家，房间尚未正式开场，`hostVoiceListen` 保持关闭。为三人签发短期 staging Bearer token，然后设置：

```text
VOICE_E2E_API_URL
VOICE_E2E_HOST_URL
VOICE_E2E_PLAY_URL
VOICE_E2E_WORLD_ID
VOICE_E2E_ROOM_ID
VOICE_E2E_HOST_TOKEN
VOICE_E2E_PLAYER_A_TOKEN
VOICE_E2E_PLAYER_B_TOKEN
```

执行：

```powershell
node scripts/staging-voice-media-e2e.mjs
```

门禁会验证：

- 主持和两名玩家都真实连接 LiveKit 主房；
- 候场密谈按钮不可用；
- 玩家刷新后回到主房并恢复媒体；
- 主持二次确认正式开场后才开放密谈；
- 受邀两名玩家能连接私房；
- 未受邀主持请求私房 token 返回 403；
- 生成三张截图和不含令牌的 `report.json`。
