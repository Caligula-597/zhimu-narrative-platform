# 三产品线工具边界与桌游原型契约

## 1. 创建入口

创建世界只要求两项：创作类型与名称。类型只开放剧本杀、跑团、桌游三条主线；创建后不自动添加角色、章节、房间或组件。

## 2. 精细工具边界

| 产品 | 专属工具 | 共享底层能力 |
|---|---|---|
| 剧本杀 | 角色私人剧本、谜底与关系、剧情编排图谱、线索管理、场内小游戏 | 自动化规则、存档与复盘 |
| 跑团 | 角色与 HO、模组编排、跑团地图与遭遇、团内小游戏 | 判定与自动化、战役存档 |
| 桌游 | 桌游设计总台、玩家席位与私密信息 | 条件与结算规则、测试局记录 |

页面只能显示当前产品支持的工具。底层可以复用上传、变量、条件、效果和存档能力，但不得把跑团的 NPC、遭遇、掷骰界面直接暴露给桌游，也不得把剧本杀的谜底与线索页暴露给桌游。

## 3. 桌游玩家席位

人物表是玩家席位的唯一数据源：

- 增加一个席位等于创建一个人物；
- “补齐为 6 人”只创建当前缺少的席位；
- 修改席位名称会同步到人物工作台；
- 删除席位会同时删除对应人物及其私人阶段内容，因此采用二次确认；
- 保存桌游设计时，最少/最多人数由真实席位数量同步，不维护第二份人数名单。

## 4. 桌游设计总台

总台分为四个模块：

1. 组件与素材：棋盘、牌堆、卡牌、棋子/资源、数值轨、骰子、计时、阶段与自定义组件。
2. 玩家席位：直接维护人物数据。
3. 条件与计算：变量、条件、效果、机制模板与实时试算。
4. 游戏说明书：目标、准备、回合流程、玩家动作、结束条件、平局和例外。

组件素材支持安全图片、PDF 和 Word。卡组与卡牌额外支持 JSON / CSV 卡表导入，导入后成为可逐项编辑的数据。视觉素材必须保留图片或文件下方的解释字段。

## 5. 基础机制模型

首批内置十二种机制起点：获得资源、支付资源、抽牌、弃牌、移动棋子、推进数值轨、骰点判定、条件奖励、翻开卡牌、阶段推进、倒计时和胜负判断。

每条规则由四层组成：触发时机、条件关系、条件列表、顺序效果列表。变量支持整局、每位玩家、指定组件三种范围，并可定义初始值、最小值和最大值。实时试算只用于设计阶段验证单条规则；它不是最终联机桌游运行器。

## 6. 可试玩原型最低门槛

系统只在以下七项全部完成时标记为“可进入真人测试”：

- 至少 2 个真实玩家席位；
- 至少 1 个桌面组件；
- 写明游戏目标与结束条件；
- 写明准备与回合流程；
- 写明玩家可执行动作；
- 至少 1 个可计算数值；
- 至少 1 条带执行效果的机制。

该判断器只保证原型形成闭环，不判断趣味性、平衡性或商业完成度。新机制应在真实案例中验证后再加入基础模板，避免一开始堆出无法理解的万能编辑器。
