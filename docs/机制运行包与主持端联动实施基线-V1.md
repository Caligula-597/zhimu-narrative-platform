# 机制运行包与主持端联动实施基线 V1

## 1. 文档目的

本文件记录 2026 年 8 月对《六号闸不等天亮》完整草稿的审查结论，并把单篇问题转化为可复用的产品与工程修改方向。

在本基线完成前，暂停继续批量生成和完整私人正文生成。当前优先级不是继续增加提示词，而是建立从创作蓝图到主持端运行房的可执行数据链路。

## 2. 核心判断

当前系统已经能在大纲校验阶段表达状态、资源、证据开关和结局条件，但这些结构没有完整进入 `world_segments` 和运行房。导入后的 Segment 主要保存主持流程、主持真相、线索发放和玩家任务；`mechanics` 仅保留来源与幕标识。

因此，当前作品属于“带机制说明的叙事文档”，尚不属于“能够由系统稳定结算的互动剧本”。继续只改生成提示词，会反复出现以下现象：

- 机制存在于说明文字中，主持人需要自行推测状态变化；
- 私人正文提前替玩家作出选择；
- 调查点只是点击后读取答案；
- 资源、区域和结局是否可达无法计算；
- 同一事实分别出现在大纲、角色档案、线索、正文和主持手册中并发生冲突；
- 第五章重新出现“公开或隐瞒”的临时选择。

## 3. 本次审查发现的共性缺口

### 3.1 缺少唯一事实源

角色、事件、授权、签名、证据与责任信息应先登记为稳定事实，再由章节、线索、主持手册和私人正文引用。不得让不同生成阶段分别重写同一事实。

角色秘密拆分为：

- `trueSecret`：真实发生且角色知道的事实；
- `coverStory`：角色为掩盖秘密而准备的解释；
- `publicClaim`：角色当前已经公开说出的主张；
- `privateKnowledge`：角色知道但不一定属于其秘密的事实。

涉及授权或代理签名时，必须增加签名矩阵：名义签署人、实际操作者、授权用途、禁止用途、生效时间、撤销条件和证据来源。

### 3.2 缺少可执行的章节状态机

每一轮必须明确：

1. 进入条件；
2. 玩家可见行动；
3. 不行动的默认损失；
4. 资源消耗；
5. 状态变化；
6. 证据解锁、降级或损毁；
7. 下一轮读取；
8. 可见反馈。

自然语言中的“影响后续”“联盟变化”“主持人酌情处理”不能代替结构化效果。

### 3.3 区域、人员、设施和证据被压缩为一个状态

区域不能只使用“已保护／未保护”。同一区域至少允许分别描述人员、证据和关键设施，例如：

```json
{
  "old_port": {
    "populationStatus": "at_risk",
    "evidenceStatus": "intact",
    "structureStatus": "damaged"
  }
}
```

是否可以恢复、每次恶化的方向和结局读取的维度必须明确。

### 3.4 调查点不是互动

每个调查点至少包含：可执行角色、具体操作、工具或权限、成本、完整结果、不完整结果、失败推进、污染或暴露风险、证据与状态效果。

同一调查对象可以有多种操作。例如对压力锁液压管可进行表面取样、拆卸逆止阀或核查便携泡沫罐，各自获得不同强度和来源的材料。

### 3.5 证据不能稳定支持结论

证据系统需要从“线索列表”升级为“结论图”。每条证据必须写明：

- 能证明什么；
- 不能证明什么；
- 常见误读；
- 原始信息根；
- 共同故障域；
- 派生关系；
- 获取行动；
- 与哪些独立证据组合后才能支持结论。

证明死因的材料不能自动证明实施者。解释全部责任链的总结文件应拆回多份原始记录，让玩家完成拼接。

### 3.6 私人正文与运行分支不兼容

私人正文不得提前决定全桌选择。关键选择位置采用以下结构：

- `preChoiceSection`：选择发生前的稳定正文；
- `optionFragments`：各选项结算后才发放的分支段落；
- `failureFragment`：条件不满足或默认损失发生后的替代段落；
- `postChoiceSection`：只读取已经结算的事实。

正文生成器只能引用允许的事实 key，可以补充感官和衔接文字，但不得新增决定性犯罪、删改记录、授权或灭证行为。

### 3.7 缺少统一故事时钟

连续危机作品必须登记总时长、轮次时长和最大可跨越时间。章节正文、调查结果和主持提示都要接受时间连续性检查，禁止在十八分钟潮窗中出现“明天检测”“明早继续”。

### 3.8 最终章仍在制造新结局变量

责任公开、秘密承认和关键资源消耗应在前四章完成并锁定。第五章只允许：

- 读取此前状态；
- 展示当前可行方案；
- 执行满足条件的最终行动；
- 按优先级匹配结局；
- 输出角色落点。

第五章不得重新询问此前应已决定的“公开或隐瞒”。

## 4. 通用机制运行包

故事特有名称不写死在通用引擎中。通用引擎保存结构，具体作品提供数据。

```json
{
  "schemaVersion": 1,
  "factLedger": [],
  "entities": [],
  "authorizationMatrix": [],
  "eventLedger": [],
  "stateRegistry": [],
  "resourceRegistry": [],
  "rounds": [],
  "actions": [],
  "investigationActions": [],
  "evidenceGraph": {
    "evidence": [],
    "conclusions": [],
    "misdirections": []
  },
  "decisionNodes": [],
  "branchFragments": [],
  "endingRoutes": [],
  "roleDisclosureStates": []
}
```

### 4.1 状态注册表

状态记录类型、初值、合法值、控制模式、首次可写章节、可写主体和是否允许恢复。

状态分为：

- `observed`：客观事实，只能由世界规则或调查确认；
- `decision`：由玩家世界内选择写入；
- `derived`：由规则根据其他状态推导；
- `runtime`：房间运行过程产生，不反向改写作者事实。

### 4.2 资源注册表

资源必须属于故事世界，包含初始值、上下限、所有者、恢复规则和可使用章节。所有消耗必须挂在具体行动或不可避免的世界事件上。

### 4.3 行动契约

每个行动统一包含：

```json
{
  "key": "action-example",
  "roundKey": "round-2",
  "actorRules": [],
  "preconditions": [],
  "choiceText": "玩家看到的世界内行为",
  "costs": [],
  "stateEffects": [],
  "evidenceEffects": [],
  "visibleFeedback": "立即可观察的结果",
  "nextReads": [],
  "onUnavailable": {}
}
```

### 4.4 结局契约

每条主要结局至少读取两个不同章节形成的条件，并声明优先级、互斥规则、默认路线和不可达时的降级处理。最终章只读取，不补造前置事实。

## 5. 创作者端与主持端的联动边界

### 5.1 创作者端

普通作者看到自然语言，不默认展示内部 key。主要编辑入口包括：

- 机制设计七问与机制卡片；
- 轮次／潮窗表；
- 区域与资源面板；
- 调查行动编辑器；
- 证据—结论关系；
- 授权与签名矩阵；
- 角色秘密、口径和公开节点；
- 结局条件预览；
- 模拟结果与可复现问题。

高级模式可以查看内部状态和引用，但所有补丁仍需作者确认。

### 5.2 后端

后端负责保存唯一机制运行包，并完成：

- schema 校验；
- 状态与资源全路径模拟；
- 证据来源独立性检查；
- 结局可达性和互斥检查；
- 角色权限与授权边界检查；
- 时间连续性检查；
- 生成内容引用检查；
- 发布版本冻结和运行房快照。

### 5.3 主持端

主持端不是文档阅读器，而是机制执行器。首期需要：

- 当前轮次与倒计时；
- 区域人员、证据和设施状态；
- 剩余许可和资源；
- 当前满足条件的行动；
- 行动代价与即时反馈；
- 线索解锁、损毁和发放；
- 角色责任公开状态；
- 当前仍可达的结局与缺失条件；
- 操作审计、检查点和受控回退。

主持人可以进行人工裁定，但每次越过系统条件都要记录原因，不能静默改写事实。

### 5.4 玩家端

玩家端只接收玩家可见行动、资源说明、即时反馈和已解锁内容，不显示 `stateKey`、结局判定式或主持人真相。

## 7. 开发阶段

### P0：冻结失败样本

- 保留当前草稿及审查意见；
- 转为回归测试夹具；
- 暂停下一轮生成。

### P1：机制运行包与导入投影

- 定义共享 schema；
- 把大纲状态、资源、决策和证据效果编译进 Segment／发布快照；
- 禁止导入时只保留 `source` 和 `actKey`。

#### P1 实施记录（2026-08-06）

已完成第一段后端基线：

- 新增共享 `mechanism-package` 契约和 schema 版本；
- 将事实、实体、授权、状态、资源、轮次、角色行动、调查行动、证据图、决策、分支和结局编译为世界级运行包；
- 对 key 唯一性及状态、资源、证据、章节、决策、结局引用进行确定性校验；
- 新增每个世界唯一的 `world_mechanism_packages` 存储，并启用 RLS；
- 含 `outline` 的流水线导入会保存运行包，并把相应轮次投影进 `world_segments.mechanics`；
- 老流水线没有 `outline` 时仍可兼容导入，但不会伪造运行包；
- 世界快照和不可变发布快照会携带并冻结运行包；
- 主持端的运行内容接口会返回运行包，玩家内容投影不返回内部状态、结局条件或主持信息；
- 已增加运行包编译、悬空引用、快照契约和迁移安全回归测试。

当前边界：调查行动只投影现有大纲已经提供的获取方式和取证操作；失败推进、污染风险及多操作分支仍需在 P2／P3 增加明确作者输入。主持端尚未执行状态事务，不能把本阶段误称为“可完整跑团”。

### P2：确定性模拟器

- 结局可达性；
- 资源提前耗尽；
- 无效或等价选择；
- 无动作死局；
- 状态类型和越界；
- 默认损失；
- 最短复现路径。

#### P2 内核实施记录（2026-08-06）

已完成无模型参与的第一版路径模拟器：按轮次读取入口条件、失败分支、公共状态写入、资源变化、证据开关、玩家决策和世界规则，输出完整选择轨迹及命中结局。当前自动报告状态类型或枚举越界、资源上下限越界、等价选项、不可达结局、多结局同时命中和路径上限截断。导入时仅保存模拟摘要，不自动修改作者内容。

#### P2 组合覆盖与作者诊断实施记录（2026-08-08）

- 调查行动按作者登记顺序枚举“跳过／成功／失败”，能够覆盖同轮多个调查的可选执行组合；没有失败契约的旧调查继续只枚举“跳过／成功”；
- 增加独立的玩家“不行动”策略：跳过全部可选调查，限时决策只执行作者显式登记的 `defaultOptionKey`；非限时决策或缺少默认方案时明确报告停在哪一轮、哪个决策形成死局，不替作者猜测选择；
- 每条确定性问题携带压缩后的最短复现路径。普通通过分支和未执行调查不会污染路径，保留实际决策、已执行调查、入口失败及不行动节点；
- 每项资源输出 `initially_exhausted`、`not_exhausted`、`avoidable`、`inevitable` 或 `inconclusive` 判定。只有覆盖完整且所有路径都曾达到下限时才报告“必然耗尽”；路径上限截断时不冒充确定结论；
- 模拟摘要同步保存面向作者的严重度、中文标题、具体原因、最短复现路径和修改方向；底层问题码继续保留，供回归测试和后续工作台稳定消费；
- 调查成功／失败分支中的状态、资源和证据引用已纳入运行包确定性校验，并增加组合、不行动、路径压缩、耗尽证明和截断保守性的回归测试。

当前尚未完成：针对主持端人工裁定的再模拟。调查失败和非限时决策的默认损失仍需作者提供显式契约；模拟器只验证、执行和诊断已登记数据，不从自然语言自动补造效果。

### P3：创作者端机制工作台

- 机制向导；
- 轮次和行动编辑；
- 调查与证据图；
- 角色秘密与授权矩阵；
- 审查收件箱。

#### P3 线上表现协议实施记录（2026-08-06）

已完成第一批跨端机制表现基线：

- 新增共享机制表现目录，首批覆盖公开抉择、资源取舍、证据质证、顺序重建、限时危机和角色承诺；
- 每种形式同时说明作者要设计什么、主持人如何结算、玩家在线上看到什么，避免三端分别发明同名机制；
- 大纲生成合同会要求逐章选择线上形式，并分别写清玩家操作、主持结算、公开方案预览、代价、风险与时限；
- 大纲决策可以登记 `interaction`，选项可以登记纯玩家可见的 `presentation`；内部状态效果仍保留在隐藏契约中；
- 未登记表现形式的旧作品继续使用“公开抉择”默认协议，不要求迁移后才能运行。

当前边界：本阶段提供的是可运行决策的跨端表现协议与生成合同，不是完整的自由机制编辑器。创作者端的可视化选择应进入独立懒加载机制工作台，避免继续扩大主应用首屏；玩家个人提交、秘密投票、自由排序和任意数值分配仍需要后续输入会话与聚合协议，前端不得提前伪装为已可用。

#### P3 机制工作台与公开倾向闭环实施记录（2026-08-06）

- 创作驾驶舱新增按需加载的机制工作台，作者无需填写 JSON，可选择六类线上表现并回答“机制设计七问”；
- 设计可以保存为草稿或作者确认版本。草稿明确标记为非既定事实，确认版本作为稳定来源进入故事总览装配和 Matrix 生成上下文；
- 玩家端可对当前公开抉择提交或修改个人倾向，仅返回自己的提交，不显示其他角色选择；
- 主持端按选项汇总人数和角色名称，并明确提示“玩家倾向仅供参考，主持结算才改变剧情状态”；
- 提交使用房间机制实例、决策 key、角色和版本号约束，旧轮次、错误选项、内容绑定变化及已关闭决策都会被拒绝；
- 新增迁移 `107_room_mechanism_decision_submissions.sql`，偏好提交与运行状态分表保存，不污染权威状态日志；
- 玩家提交事件仅供主持端刷新聚合，玩家侧只接收游标心跳，避免从实时事件推断他人的选择。

该阶段边界：当时完成的是公开单选倾向，不是匿名投票；秘密承诺、自由排序、数值分配、倒计时默认和主持端一键按多数结算仍需分别设计，不能复用公开倾向接口冒充完成。

#### P3 秘密承诺与限时默认闭环实施记录（2026-08-06）

- `role_commitment` 采用独立的 `private_choice` 提交语义：玩家只看到自己的承诺回显，其他玩家无法取得个人选择，主持端可以按角色核对；
- `timed_crisis` 必须同时登记正数时限和一个真实存在的默认选项，缺失或悬空引用会在运行包校验阶段被拒绝；
- 新增迁移 `108_room_mechanism_round_clock.sql`，每个房间机制实例持久化当前轮次的服务器开始时间，进入下一轮时才重新计时；
- 玩家端显示服务端推导的截止时间和超时默认方案，到期后界面停止提交；后端也会拒绝过期提交，不能通过修改本地时间绕过；
- 主持人在到期前可以正常确认玩家方案；到期后普通选项被关闭，只能执行作者预设默认方案，且后端再次校验时钟和选项；
- 超时结算来源写入行动审计，能够区分主持正常确认与到期默认执行。

当前边界：这是“服务端判定到期、主持端触发默认结算”，不是后台定时任务自动推进。这样可避免无人主持时系统自行改写正在恢复或暂停的房间；若未来需要真正自动推进，应另建可暂停、可抢占、幂等的调度器。自由排序、数值分配和按多数一键结算仍属于下一阶段，不能用单选提交协议伪装完成。

### P4：主持端执行器

- 运行状态存储；
- 行动事务结算；
- 线索和分幕分支发放；
- 潮窗与区域面板；
- 结局可达性提示；
- 检查点和审计。

#### P4 执行内核与主持面板实施记录（2026-08-06）

已完成第一版主持端执行闭环：

- 新增房间级机制运行态与追加式行动日志，运行态绑定发布版本／草稿修订和机制包摘要；
- 主持端可初始化运行态、读取当前轮次、执行玩家决策、结算调查行动和推进轮次；
- 每次写操作都要求上一版本号并支持幂等键，避免双击、重试或多主持人并发造成重复结算；
- 状态、资源和证据变化由共享确定性内核结算，越界或悬空引用会在入库前被拒绝；
- 主持人可以进行人工裁定，但必须填写原因，只能修改已登记的状态、资源或证据，并留下版本边和审计记录；
- 新版房间检查点会保存机制运行态，恢复时不倒拨版本号，而是追加一条 `override` 审计边；
- 旧版检查点未捕获机制运行态时默认不改动现状，跨房间恢复不会复制机制状态；
- 主持接口返回完整运行态和历史，玩家内容接口不暴露内部状态 key、结局条件或主持信息；
- 发布绑定统计已纳入机制运行态和行动日志，开始运行后不能静默切换到另一内容版本。
- 主持监控台已增加按需加载的“机制运行”面板，展示当前轮次、状态、题材资源、证据、待决选择、调查动作、最近变化和命中结局；
- 面板可以初始化、结算选择、结算调查和推进轮次，提交期间会锁定重复操作，房间切换后的迟到响应不会污染新房间。
- 后端会从房间当前状态重新枚举剩余合法路径，主持面板可查看各结局是否仍可达及当前缺失条件；路径过多时明确标记截断，不伪装成完整结论。
- 主持端和玩家端现在读取同一 `interaction` 表现协议：主持端显示结算说明、题材资源、时限与方案风险，玩家端只显示公开操作说明和方案预览，不暴露效果映射、资源 key 或结局条件。

当前尚未完成：后台调度器自动推进、调查失败与“不行动”默认损失的完整作者契约、人工裁定的高级前端表单，以及线索发放到现有角色可见内容的自动联动。限时危机已经具备服务端截止时间和主持触发的默认结算，但不冒充无人值守自动推进。生产数据库迁移保持待部署，需随正式后端发布执行。

## 8. 首期验收标准

首期不以“AI写得更长”为验收标准。完成应同时满足：

- 作者无需填写 JSON 即可建立五轮可执行机制；
- 运行包能进入发布快照和运行房；
- 主持端能够执行行动并自动结算状态、资源和证据；
- 每条主要结局至少存在一条可复现路径；
- 不行动也有明确且可继续的结果；
- 私人正文不会预先决定尚未发生的选择；
- 第五章不补造前四章遗漏的责任状态；
- 系统能够报告事实冲突、时间冲突和证据不足，而不是只验证 JSON 字段完整。
