# 织幕长线剧本杀自动化叙事与运营平台软件 V1.0 操作说明书

## 一、软件概述

织幕长线剧本杀自动化叙事与运营平台软件是一套面向线上长线剧本杀、跑团和互动叙事创作运营的软件系统。软件围绕剧本创作、内容编排、房间运行、玩家互动、主持控制、复盘归档和运营管理形成完整流程。

系统包含四类主要入口：

- 主应用：用于创作者、运营人员和管理员进行剧本世界管理、内容编辑、房间管理、资产管理和运营查看。
- 玩家端：用于玩家加入房间、阅读角色内容、查看线索、参与互动、查看复盘。
- 主持端：用于主持人监控房间、推进流程、管理玩家状态和处理现场事件。
- 官网：用于产品展示、公开入口、内测申请和商业信息展示。

## 二、运行环境

服务器端运行环境：

- Node.js
- Fastify
- PostgreSQL
- 对象存储服务
- 可选监控、告警、链路追踪和上传扫描服务

浏览器端运行环境：

- 现代桌面浏览器
- 现代移动浏览器
- 支持 JavaScript、HTML5、CSS3 和 SSE 事件通信

部署环境：

- 主应用与 API 可部署于全栈托管环境。
- 玩家端、主持端和官网可采用静态站点托管。
- 生产环境通过 API 域名为多端应用提供统一数据能力。

## 三、系统模块

### 1. 账号与权限模块

账号与权限模块用于用户注册、登录、会话维持、账号资料管理、权限判断和访问控制。系统通过后端接口判断用户身份和角色，不依赖前端隐藏内容作为安全边界。

主要功能包括：

- 用户注册和登录。
- 会话 Cookie 管理。
- OAuth 账号接入。
- 账号资料和权益查看。
- 角色、房间、世界和运营权限校验。
- 统一错误返回和接口限流。

### 2. 世界与剧本管理模块

世界与剧本管理模块用于创建和管理互动叙事内容。创作者可以建立世界，编辑章节、角色、场景、线索、物品和规则，并对内容进行版本化管理。

主要功能包括：

- 创建剧本世界。
- 编辑世界基础信息。
- 管理角色槽位。
- 管理章节与剧本段落。
- 管理场景、线索和物品。
- 管理自动化规则。
- 查看公开剧本库和内容审核状态。
- 管理世界版本和发布准备状态。

### 3. 创作编辑模块

创作编辑模块用于组织长线剧本内容。系统支持按角色、章节、场景和信息层级整理内容，帮助创作者将叙事材料转化为可运行的互动剧本结构。

主要功能包括：

- 角色信息编辑。
- 章节内容编辑。
- 剧本段落管理。
- 导入文档并提取结构。
- 生成或调整角色剧本。
- 查看内容完整性和发布准备状态。

### 4. 编排与线索模块

编排与线索模块用于管理故事运行中的关键对象和信息关系。创作者可以维护线索、物品、场景和信息流转关系，为玩家解锁、主持推进和复盘提供基础。

主要功能包括：

- 线索创建、编辑和归类。
- 物品创建、编辑和归类。
- 场景关系维护。
- 线索可见性和归属关系管理。
- 线索分享与审计。
- 剧情信息结构化检查。

### 5. 规则引擎模块

规则引擎模块用于描述和执行结构化规则。系统禁止用户直接提交任意 JavaScript 执行，而是通过结构化条件和动作完成规则触发，降低安全风险。

主要功能包括：

- 创建规则。
- 设置规则条件。
- 设置规则动作。
- 预览规则执行结果。
- 在房间运行过程中触发规则。
- 记录规则执行日志。

### 6. 房间运行模块

房间运行模块用于将剧本模板转化为一次具体运行实例。每个房间独立保存玩家成员、阅读进度、线索持有、物品状态、事件日志、检查点和复盘内容。

主要功能包括：

- 创建运行房间。
- 邀请玩家加入房间。
- 绑定玩家角色。
- 查看玩家阅读进度。
- 推进章节和阶段。
- 处理主持事件。
- 记录房间事件日志。
- 创建检查点并支持恢复。

### 7. 玩家端模块

玩家端用于玩家参与剧本运行。玩家可以登录或通过邀请进入房间，查看与自己角色相关的内容，阅读章节，查看线索，参与社交互动，并在结束后查看复盘。

主要功能包括：

- 加入房间。
- 查看角色首页。
- 阅读角色章节。
- 查看已获得线索。
- 查看物品和任务。
- 参与广场和社交互动。
- 查看复盘内容。
- 使用移动端友好的导航。

### 8. 主持端模块

主持端用于主持人在运行过程中进行监控和控制。主持人可以查看房间状态、玩家进度、成员情况、事件记录，并执行推进、确认、延迟、踢出等管理动作。

主要功能包括：

- 查看房间总览。
- 查看玩家列表和角色绑定。
- 查看玩家进度。
- 推进房间事件。
- 管理主持确认流程。
- 处理玩家异常状态。
- 查看事件日志。

### 9. 资产与上传模块

资产模块用于管理封面、剧本资料和相关文件。系统支持对象存储、上传策略、文件回收和安全扫描，生产环境可配置严格上传检查。

主要功能包括：

- 上传世界封面。
- 上传剧本相关资产。
- 查看资产列表。
- 删除和回收资产。
- 对上传文件执行安全扫描。
- 配置对象存储。

### 10. 存档与复盘模块

存档与复盘模块用于记录房间运行状态、阶段进展和最终结果。系统支持检查点、恢复、房间事件日志和复盘叙事生成，便于主持人与玩家回顾过程。

主要功能包括：

- 创建房间检查点。
- 恢复房间状态。
- 记录关键事件。
- 生成复盘摘要。
- 查看玩家复盘页。
- 导出或查看归档内容。

### 11. 运营管理模块

运营管理模块用于平台运维、内测支持、内容审核、公开库管理、用户反馈和生产状态查看。管理员可以通过 OPS 页面查看系统健康状态和生产门槛。

主要功能包括：

- 查看系统健康状态。
- 查看生产可信门槛。
- 查看告警与监控配置。
- 管理公开剧本库。
- 管理内测申请。
- 查看用户反馈。
- 查看计费和权益相关状态。

## 四、典型操作流程

### 1. 创建剧本世界

1. 用户登录主应用。
2. 进入世界管理或创作者首页。
3. 点击创建世界。
4. 输入世界名称、简介、类型和基础设定。
5. 保存后进入创作编辑界面。
6. 继续添加角色、章节、线索、物品和规则。

### 2. 编辑角色与章节

1. 进入指定世界。
2. 打开创作编辑模块。
3. 选择角色管理，创建或编辑角色槽位。
4. 选择章节管理，创建章节内容。
5. 为不同角色配置可见内容。
6. 保存修改并检查完整性。

### 3. 管理线索和物品

1. 进入编排或线索模块。
2. 新建线索，填写名称、描述、关联章节和可见规则。
3. 新建物品，填写名称、说明和持有关系。
4. 保存后在房间运行过程中按规则或主持操作进行发放。

### 4. 配置自动化规则

1. 进入规则模块。
2. 创建新规则。
3. 设置触发条件，例如章节进度、玩家状态或线索状态。
4. 设置执行动作，例如解锁内容、发放线索、记录事件。
5. 使用预览功能检查规则结果。
6. 保存并应用于运行房间。

### 5. 创建运行房间

1. 在主应用中选择已准备好的世界。
2. 点击创建房间。
3. 配置房间名称、参与人数和运行参数。
4. 生成邀请链接。
5. 将邀请链接发送给玩家。
6. 玩家加入后绑定角色并开始阅读。

### 6. 玩家加入与阅读

1. 玩家打开邀请链接。
2. 登录或进入玩家端。
3. 加入指定房间。
4. 选择或确认角色。
5. 查看角色首页和章节内容。
6. 按主持推进或规则解锁继续阅读。
7. 查看线索、物品和复盘内容。

### 7. 主持推进房间

1. 主持人进入主持端。
2. 选择目标房间。
3. 查看玩家加入情况和阅读进度。
4. 按流程推进章节、发放线索或处理事件。
5. 查看事件日志确认操作结果。
6. 在关键节点创建检查点。

### 8. 复盘与归档

1. 房间结束后进入复盘模块。
2. 系统汇总玩家进度、线索、事件和关键记录。
3. 生成复盘摘要。
4. 玩家在玩家端查看复盘结果。
5. 主持人或运营人员查看归档记录。

## 五、异常处理

系统对异常情况提供统一提示和后端校验：

- 未登录或会话失效时，提示重新登录。
- 权限不足时，禁止访问目标资源。
- 表单数据不完整时，提示补齐必填项。
- 房间或世界不存在时，返回明确错误。
- 上传文件不符合要求时，拒绝上传并提示原因。
- 生产配置缺失时，OPS 状态页显示未达标项。

## 六、系统安全说明

系统采用后端权限判断作为主要安全边界，并提供以下安全能力：

- HttpOnly 会话 Cookie。
- API 限流。
- CORS 控制。
- 安全响应头。
- 上传安全扫描。
- 操作审计。
- OPS 和 Metrics Token。
- PostgreSQL Row-Level Security。
- 统一错误格式。

## 七、维护与部署

开发人员可通过脚本完成本地启动、构建、测试、生产检查和部署验证。常用命令包括：

```powershell
cd backend
npm run dev

cd ..
npm run dev
npm run build
npm run test:e2e
```

生产环境部署前建议执行：

```powershell
cd backend
npm run check
npm run check:schemas
npm run check:boot
npm test

cd ..
npm run check:modules
npm run build
npm run test:play
npm run test:host
npm run check:production-ready
```
