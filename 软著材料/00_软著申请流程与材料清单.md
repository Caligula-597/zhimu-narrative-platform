# 织幕软著申请流程与材料清单

适用软件建议名称：织幕长线剧本杀自动化叙事与运营平台软件 V1.0

## 一、建议结论

建议先按一个整体软件申请：

- 软件全称：织幕长线剧本杀自动化叙事与运营平台软件
- 软件简称：织幕
- 版本号：V1.0
- 软件类型：应用软件 / 网络平台软件 / SaaS 管理平台
- 开发方式：独立开发
- 权利取得方式：原始取得

后续如需融资、招投标、客户合作或拆分资产，可再补充申请：

- 织幕剧本创作与运营管理平台软件 V1.0
- 织幕玩家互动剧本阅读系统软件 V1.0
- 织幕主持人房间控制台软件 V1.0
- 织幕智能剧本生成与结构化处理系统软件 V1.0

## 二、办理流程

1. 确认申请主体
   - 个人申请：准备身份证明。
   - 公司申请：准备营业执照副本复印件/扫描件，通常需加盖公章。

2. 确认软件基础信息
   - 软件全称、简称、版本号。
   - 开发完成日期。
   - 发表状态与首次发表日期。若 V1.0 已经通过 `getzhimu.com` 或 `app.getzhimu.com` 面向公众提供访问或使用，建议按“已发表”核对；仅有宣传页、未向公众提供软件功能时，再按实际情况判断。
   - 开发方式、权利取得方式。
   - 主要功能、运行环境、技术特点。

3. 整理软件鉴别材料
   - 源程序：通常整理前、后各连续 30 页，共 60 页；每页不少于 50 行。代码不足 60 页时提交全部。
   - 文档：通常提交操作说明书或设计说明书，前、后各连续 30 页；每页不少于 30 行。文档不足 60 页时提交全部。

4. 在线填写登记申请表
   - 登录中国版权保护中心相关登记系统。
   - 按申请主体、软件信息、开发信息、发表信息、权利信息填写。
   - 核对无误后提交/打印需要签章的文件。

5. 提交材料
   - 登记申请表。
   - 软件源程序鉴别材料。
   - 软件文档鉴别材料。
   - 身份证明/营业执照。
   - 如涉及委托、合作、转让或职务开发争议风险，补权属证明材料。

6. 受理与补正
   - 等待形式审查。
   - 如收到补正通知，按通知修改名称、材料页数、签章或权属证明。

7. 取得登记证书
   - 审查通过后取得计算机软件著作权登记证书。

## 三、织幕项目已具备的材料基础

本项目已经具备申请基础（材料边界更新至 2026-08-08，功能实现证据截至 2026-08-07）：

- 自主源代码：本次整理纳入 1,011 个源文件、约 140,751 行源代码。
- 后端：`backend/src`，覆盖 Fastify API、PostgreSQL 数据层、账号与权限、安全、规则引擎、AI 矩阵流水线、房间运行和运营管理等模块。
- 创作者端：`src`，覆盖创作驾驶舱、世界管理、创作宪法、活态故事总览、语义大纲、角色与章节、编排、规则、资产、账户和 OPS 等视图与运行时。
- 玩家端：`play/src`，覆盖加入房间、阅读、调查、线索、笔记、语音、广场社交和复盘等功能。
- 主持端：`host/src`，覆盖主持控制台、房间状态、玩家管理、事件推进和运行数据同步等功能。
- 共享层：`shared`，覆盖 session token、api-fetch、toast、status-chip、SSE 等跨端共享能力。
- 数据库迁移：`backend/migrations`，记录账号、权限、内容、房间、创作者结构、玩家增强和运行安全等数据结构演进。
- 测试与脚本：包含后端测试、E2E 测试、构建部署、备份恢复和材料生成脚本。
- 产品文档：包含架构、平台地图、功能地图、产品状态、前端说明、运维、备份演练和机制设计等文档。

## 五、建议提交版本边界

建议以当前公开 Beta 前夜版本作为 V1.0 申请边界，重点描述以下能力：

- 剧本/世界创建、编辑、版本管理、世界模板、向导引导。
- 角色、章节、线索、物品、场景、调查点、故事图谱、自动化规则管理。
- 创作者圣经（角色档案、伏笔时间线、真相重构、文学风格、时代设定等结构化创作底座）。
- 活态故事总览：综合世界简介、角色、关系、核心事实和章节形成故事脊柱候选，区分作者已确认、AI 暂拟与待决定内容。
- AI 矩阵辅助生成（大纲、分幕、角色脚本、实体解锁、公平性校验、杀手/无辜者推理、知识审计）。
- 机制设计工作台：创作者选择公开抉择、资源取舍、证据质证、顺序重建、限时危机或角色承诺等线上表现，并填写机制七问、保存草稿或确认为生成上下文。
- 玩家决策提交：玩家在当前轮次按公开倾向或秘密承诺模式提交选项；服务端校验房间成员、角色、运行版本与截止时间，重复提交以同一玩家/角色的最新选择覆盖。
- 主持端权威结算：主持端查看玩家提交汇总、剩余时间和作者预设默认方案，由主持人确认最终选项；服务端以期望修订号、作品绑定和轮次时钟为准写入唯一权威运行态并记录审计事件。
- 机制跨端同步与隐私：机制状态和提交数量通过房间事件同步；玩家侧只接收公开句柄和自身提交结果，不暴露作者内部机制键，秘密承诺的身份与内容仅主持端可见。
- 房间创建、玩家加入、角色绑定、主持推进、实时事件 SSE、房间事件日志。
- 玩家端阅读、线索查看与分享、笔记、投票、私密行动、怀疑度、口供、玩家任务。
- 玩家广场、社交互动、公开房间列表、内容审核。
- 主持端控制台、房间监控、玩家状态管理、小玩法、主持确认与延迟事件。
- 语音房间（LiveKit）接入。
- 存档检查点、恢复、复盘叙事生成、复盘查看。
- 资产上传、内容导入、文档解析、内容包导入导出、上传安全扫描。
- 账号、OAuth、六位邮箱验证码、邮件验证链接、密码重置、会话管理、权限矩阵、限流、审计、安全头和 RLS。
- Creator、Host、Player 三端统一账号登录，并分别维护显示名称与头像。
- 用户自备 API Key（BYOK）模型连接，可配置多家服务商；平台自有 API Key 不进入普通用户模型池。
- 账号权益、世界数量、单文件大小和存储容量配额；平台积分、付费套餐和平台自有 API 额度在 V1.0 内不对普通用户开放。
- 运营管理：OPS 状态、生产门槛检查、监控、告警、备份恢复、内测申请管理、反馈处理、公开库审核。
- 四端部署：主应用+API（Railway）、玩家端/主持端/官网（Cloudflare Pages）。

## 六、本轮版本冻结与材料更新流程

1. 以上一版 `2026-08-06_织幕V1.0` 为对照基线，确认本轮功能实现提交与代码文件范围。
2. 将机制设计、玩家提交、主持权威结算和跨端同步写入申请表功能摘要及操作说明书，避免把玩家“倾向提交”误写成最终结算。
3. 重新生成源程序交存稿：前 30 页连续覆盖创作者机制设计与共享交互合同，后 30 页连续覆盖玩家提交、主持端操作和服务端权威结算；每页保持 50 行。
4. 生成 DOCX 与 PDF，逐份核对软件名称、版本号、目录导读、页码、页数、截图、功能描述和源代码页际连续性。
5. 运行包校验，确认 4 份正式 DOCX、对应 PDF、清单、README、manifest 与新增功能证据一致后再压缩交付。
