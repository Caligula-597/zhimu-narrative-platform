## 二、里程碑（建议节奏）

### 里程碑 0：宣传快赢（1 周内，无需改架构）

**目标**：用最低成本提升第一印象。

| 任务 | 动作 |
|---|---|
| M1 | 改 `site/index.html` hero 文案 + 加"使用前后对比卡" + 加"不是什么对照" |
| M2 | staging 截三端真实图，替换 `zhimu-product-hero.png` 占位 |
| M3 | 创意提案 HTML 与官网对齐，补技术亮点 + 数据 |
| M5 | onboarding 表单提交后加即时引导，与注册入口互通 |
| P3 | 视图切换加骨架屏 |

**验收**：官网预览（`cd site && npm run dev`）肉眼检查 + 创意提案 HTML 浏览器打开无错。

### 里程碑 1：主应用架构债清理（核心，2-4 周）

**目标**：A1 + A2 + A3 完成，主应用与 play/host 同等模块化水平。

**执行顺序**（每步独立验证）：

1. **A4 起步**：先抽 `shared/security.js`（复制 play 版），play/host 改 import，主应用暂不动
2. **A1 第 1 批**：迁基础层 `utils/format.js`、`utils/user-messages.js`、`dom.js`、`state.js`（A2 分片同步）
3. **A3**：拆 `api/client.js` 为领域模块，主应用代码逐步改 import
4. **A1 第 2 批**：迁 runtime 层（`session-auth`、`auth-session`、`nav-shell`、`view-loader`、`data`、`actions-*`）
5. **A1 第 3 批**：迁 views 层（每个 view 独立迁，迁完跑 build + e2e）
6. **A1 收尾**：删 `frontend/main.js` 的 import 列表，改为入口 `app.js`，删 `window.zhimuXxx` 桥接

**每步验收命令**：
```powershell
npm run check:modules
npm run build
npm run test:e2e -- --project=chromium
```

**风险与回滚**：
- 每个文件迁移是一个独立 commit，可单独 revert
- 保留 `window.zhimuXxx` 桥接直到全部迁完
- 任何一步 e2e 红立即停，不继续下一步

## 四、风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| A1 迁移中引入回归 | 中 | 高 | 渐进式 + 每步 e2e + 保留 window 桥接 |
| CSP enforce 后误伤 | 中 | 中 | report-only 观察一周，逐条整改 |
| shared/ 抽取后三端构建断 | 低 | 中 | alias 配置 + 各端 build 验证 |
| 后端聚合 API 缓存失效逻辑错 | 低 | 中 | 聚合接口只读 + 写操作显式 invalidate |
| Pages 三站首次部署失败 | 中 | 低 | 先在 staging 跑 `pages:smoke` |
| pilot 团队不愿公开案例 | 中 | 低 | 脱敏 + 匿名 + 双方确认 |
| Stripe 启用延迟 | 高 | 低 | 维持人工扩容，pricing-commercial 不公开 |

## 五、不在路线图内的事（明确排除）

- ❌ 不引入 React/Vue/Svelte 等框架
- ❌ 不引入 Redux/Zustand 等状态库
- ❌ 不引入 GraphQL
- ❌ 不引入微前端
- ❌ 不引入 SSR/SSG（官网可考虑预渲染，但不强制）
- ❌ 不重写后端
- ❌ 不改数据库 schema 或 API 契约
- ❌ 不动 `docs/`、`.github/`、`deploy/` 等现存文件

## 七、最终目标

完成 P0 + P1 后，织幕应达到：

| 维度 | 目标状态 |
|---|---|
| 架构 | 主应用与三端同等模块化，shared/ 共享层消除重复 |
| 性能 | 首屏 < 1.5s，视图切换 < 200ms，API 有缓存 |
| 安全 | CSP enforce，innerHTML 审计进 CI，security 统一 |
| UI/UX | 三端组件复用，主应用移动端可用，骨架屏全覆盖 |
| 后端 | 面向 UI 的聚合 API，减少首屏请求数 |
| 产品 | 官网故事化 + 真实案例 + 锋利定位 |
| 宣传 | 创意提案与官网对齐，pilot 案例持续产出 |

**核心判断标准**：一个新用户从官网到主应用注册、创建第一个世界、开测试房、邀请自己进玩家端走完一遍，全程不需要看文档、不需要问运营、不需要刷新页面。
