【正文】

一、Demo 简介

是什么：织幕（Zhimu）是一个面向线上长线剧本杀 / 跑团的自动化互动叙事引擎平台，形态为四端 SaaS 网站（官网 + 创作者主应用 + 玩家端 + 主持端），并适配移动端。创作者在云端编排世界、场景、线索与自动化规则；主持人开平行运行房、监控进度、确认关键节点；玩家通过邀请码选角，阅读私人分幕、探索场景、收集线索——所有运行态实时同步，故事可以持续数周甚至数月。

面向谁：
1. 剧本创作者 / 写作者——想把故事做成可互动的线上体验，但不会编程
2. DM / 主持人 / GM——在线上带团，苦于手动管理玩家进度和线索太繁琐
3. 剧本杀玩家 / 故事爱好者——喜欢剧本杀但没时间去线下，想体验更长线的深度剧情

主要功能（3 个核心能力）：

1) 创作者云端编排 + AI 创作流水线
- 五步创建向导：世界 → 章节 → 角色 → 序章 → 测试房，一键生成可跑通的剧本骨架
- 剧情编排台：可视化图谱，场景 / 线索 / 调查点拖拽连线、自动布局，前后端坐标同步
- 自动化规则引擎：JSON 条件（阅读完成、线索持有、物品、变量比较 + all/any/not）→ 动作（解锁分幕 / 场景、发放线索 / 物品）；host_confirm 进入主持待确认队列
- DeepSeek 分层 AI 创作流水线：立项 → 逐章总剧情 → 角色私人本 → 评判 → 汇总同步到编排图
- 内容包导入导出：JSON / Markdown / TXT / DOCX，importKey 去重

2) 主持人自动化运行台
- 平行运行房：同一剧本开多房间，独立邀请码、进度、日志、语音，互不污染
- 实时监控：SSE 推送玩家阅读 / 调查 / 线索事件，玩家进度表与待确认事件队列
- 关键节点确认：规则触发的待确认事件可批准 / 拒绝 / 预览动作，支持延迟调度
- 存档与回滚：Checkpoint 快照 v2 + 9 域 scoped restore，跨平行房恢复 + 审计日志

【截图位置 2：主持台 - 运行房玩家进度 + 待确认事件】

3) 玩家碎片化体验 + 复盘
- 邀请码选角 → 私人分幕阅读（防抖自动保存）→ 场景探索与线索收集
- 线索私享（公开到全房间 + 写「我的解读」）、LiveKit 语音房
- 复盘报告：玩家「我的视角」+ 主持「全局复盘」

二、Demo 创作思路

灵感来源：源于一群剧本杀爱好者的真实痛点——每次组局都像一场小型项目管理，约人、订场、凑时间，精力花在了故事之外。而那些真正精彩的长线剧情，往往因为主持太累、玩家时间难凑而半途夭折。线下本又贵又难约；线上文字群玩体验混乱，翻记录翻到吐，全靠 DM 脑子记；现有工具要么太复杂（跑团骰子 Bot 只会掷骰子），要么太简单（文档共享毫无沉浸感）。

想解决的问题：
- 让长线剧情能持续：故事可以开数周数月，不用每次重新讲
- 让主持不累：规则自动触发、进度自动同步、关键节点才需人工确认
- 让好本子能复用：同一剧本可开多平行房，剧本模板与运行实例严格分离

为什么做这个方向：剧本杀 / 互动叙事是「内容驱动 + 社交连接」的赛道，线下受限于场地时间，线上缺结构化工具，中间存在明确的产品空白。不追「全功能跑团引擎」的大而全，聚焦「长线剧本杀自动化运行」这一垂直痛点，用规则引擎 + AI 创作流水线把重复劳动自动化。

四、TRAE 实践过程

本项目从创意提案到可体验的公开 Beta，全程使用 TRAE 驱动开发。主要流程：

1. 创意提案与架构设计：用 TRAE 梳理产品定位、目标用户与价值主张，产出创意提案 HTML；设计剧本模板（worlds / chapters / scenes / clues）与房间运行实例（rooms / player_states / rule_executions）双域分离架构，确定四端 SaaS 分域拓扑，后端 Fastify + PostgreSQL 作为唯一真相源。

2. Alpha 核心闭环：用 TRAE 搭建运行态与主持台——数据诚实（移除硬编码演示数据）、主持台运行时（玩家进度 / 待确认事件 / 手动发线索）、编排台编辑、SSE 房间事件实时推送、Checkpoint 存档。

3. Beta 产品化迭代：LiveKit 语音房、线索私享、找回密码（Resend）、OAuth 身份底座、配额守卫、主持—玩家联动（nudge / 复盘模态 / 审计卡片）、内容包导入去重与稳健性加固。

4. 生产门槛与工程化：L1 生产门槛 productionTrust 7/7（CSP enforce、OTLP、告警 webhook、上传 AV strict + ClamAV、OPS / metrics token）、监控值班 drill 6/6、权限矩阵 27 项抽查、Staging 隔离、GitHub Actions → Railway + Cloudflare Pages 部署。

5. 架构重构：单体 app.js 拆至 50+ 模块、三端共享层 A1–A4、状态分片迁移为独立 store、window.* 桥移除（主 chunk -6.2%）。

量化验收：后端单测 347 项、路由 Schema 门禁 62 条、SQL 迁移 26+ 次、UI smoke 44 项、Playwright E2E 15 项（Chromium / Firefox / WebKit 矩阵）、生产级 SaaS 评分 84 / 100。
